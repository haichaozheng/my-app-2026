# Week 05 教学计划

## 本周主题

研究设计 — 方法审计配置与"生成→审计→裁决→定稿"循环

> Phase 2: Design 第2周，阶段成果二。"做对"比"做出来"重要；方法选择是研究者的核心判断，不可委托给 AI。本周**不教"所有方法"**，而是让学生为自己的研究方法构建**可被智能体加载、可随研究修订的审计配置**——方法知识在审计追问中按需检索、在裁决中内化；偏误自检是人机交互的关键素养。

## 学习目标

- 能说明"做对"比"做出来"重要：方法选择是研究者的核心判断，不可委托给 AI
- 能说明方法审计配置的思路：不是学完所有方法再做设计，而是构建可被智能体加载、可随研究修订的配置（方法条目、设计模板结构、追问规则），方法知识在审计追问中按需检索、在裁决中内化
- 能为自己的研究方法构建**方法审计配置 v1**（方法条目元类别标签 + 设计模板结构 + 追问规则）
- 能运行五层五角色设计-审计多智能体完成**五阶段循环**：路由确认→草案生成→检索型审计→学生裁决与定稿→记录与交付
- 能说明五个角色（W5-Lead / Router / Design Draft Generator / Auditor / Audit Scribe）的职责与权限纪律
- 能对设计草案逐字段做显式确认或标记待定；大幅修改时触发 Generator 局部重生成
- 能对比至少 2 种方法论框架并说明选择逻辑（作为路由确认环节的知识支撑）
- 能对研究设计做偏误自检，判断 AI 方法建议的可信度

## 教学步骤（3节课）

**第1节 · 为什么是审计配置 + 方法论知识支撑（45 分钟）**

1. 教师分享：嗨皮诸葛项目调研（5 分钟）：用自己在"嗨皮诸葛"项目中的用户调研经历开场——怎么进入社区、听到哪些原话、哪条原话推翻了最初设想，衔接到"做研究也要先搞清楚为谁、解决什么"
2. 理念转向（12 分钟）："做对"比"做出来"重要；为什么本周不教"所有方法"——方法知识按需检索、在裁决中内化；方法审计配置是什么（可被智能体加载、可随研究修订），它与"一次性的 prompt 模板"有何不同
3. 方法论知识支撑（18 分钟）：为路由确认提供知识地图——理论框架构建（问题为什么需要这个框架、如何指导假设推导）；因果推断方法论（DID/RDD/IV/面板回归的前提假设与局限）；变量与测量（理论概念→操作化变量）
4. 💡 课堂互动：给定一个研究问题，全班分两半分别论证 DID 与 IV 的适用性，各 3 分钟陈述，教师点评（10 分钟）——这就是"路由确认"要做的判断

**第2节 · 五层五角色架构与五阶段循环（45 分钟）**

5. 新闻引子：十大券商看后市（5 分钟）：以"A股节后有望迎修复行情"新闻开场（[澎湃新闻 2026-10-08](https://news.qq.com/rain/a/20261008A039YI00)），抛出问题——"节后修复行情"是因果判断还是相关现象？要严谨验证"国庆效应"需要什么研究设计？这就是**审计追问**的姿态：对着一个论断逐字段追问依据
6. 架构讲解（15 分钟）：五层五角色（基于 [opencode agents](https://opencode.ai/v2/docs/agents/) 实现）——

   | 层 | 角色 | 模式 | 职责 | 权限纪律 |
   |---|---|---|---|---|
   | 编排层 | W5-Lead | primary | 推进五阶段流程，传递 W4 输入和路由条目 | 不调 MCP、不写文件、不做判断；subagent 白名单仅四个 |
   | 路由层 | Router | subagent | 按条目元类别标签加载设计模板结构与追问规则 | 只选文件，不生成内容 |
   | 生成层 | Design Draft Generator | subagent | 主动生成完整设计草案，逐字段标注依据、置信度、待核验点 | 可读 W3/W4 输入；可调学术搜索 MCP 查先例；只写草案 |
   | 审计层 | Auditor | subagent | 按字段追问；按需检索证据；受控写回；对修改后字段重新追问 | 检索结果只构成建议，不直接写回；写回须用户指令触发 |
   | 记录层 | Audit Scribe | subagent | 记录草案、diff、用户原话、修改理由、检索证据、修订历史 | 只写不读，不调 MCP |

7. 五阶段流程演示（15 分钟）：携 W4 输出（问题陈述 + 协变量结构 + Gap 证据表）走一遍完整循环：
   ```
   ① 路由确认：学生确认方法条目 → 加载设计模板结构与追问规则
   ② 草案生成：Generator 产出完整草案（逐字段带依据/置信度/待核验点）
   ③ 检索型审计：Auditor 逐字段追问 → 按需检索方法论先例/文献证据/复现性检查
      → 带证据再追问 → 用户裁决 → 受控写回 → 重新追问
   ④ 学生裁决与定稿：每个字段显式确认或标记待定
   ⑤ 记录与交付：Scribe 整理草案、diff、检索证据、裁决理由、修订历史
   ```
8. 方法审计配置的结构（10 分钟）：方法条目元类别标签、设计模板结构、追问规则三要素；学生将构建自己的 v1，随研究修订

**第3节 · 个人五阶段循环实操（45 分钟）**

9. 路由确认（10 分钟）：每人确认自己的方法条目（结合第1节的方法论知识支撑），加载对应设计模板结构与追问规则
10. 循环实操（20 分钟）：草案生成→审计追问→裁决/修改指令→受控写回→重新追问；每个字段显式确认或标记待定，大幅修改触发 Generator 局部重生成。💡 课堂互动：抽取 2-3 位同学投屏自己的"审计追问—学生裁决"片段，全班评估裁决质量（3-4 分钟）
11. 偏误自检（10 分钟）：如何判断 AI 方法建议是否可信；对照 Auditor 检索到的证据做交叉检验
12. 阶段收束（5 分钟）：Phase 2 完成，预告 Phase 3 研究实施（W6 数据三路径与 StatsPAI 实证）
