## 第2节 · 工具环境搭建演示

> 课前发 `weeks/week01/setup.md`（学生课后自行安装）。本节教师投屏演示，学生观察、记录课后安装时最容易卡住的步骤。

### 2.1 Python 3.13 + Cursor

- 全班统一 **3.13**，不点官网首页 3.14，不装 Anaconda
- 终端 `python --version` 须为 3.13.x
- Cursor 里 `Ctrl+Shift+P → Python: Select Interpreter`，选路径里有 `Python313` 的
- 不要选 `anaconda3`，不要选 WindowsApps 商店别名
- 已装 Anaconda 的：`conda config --set auto_activate_base false`，重开终端
- 先装 `pandas jieba`（数据分析 + 中文分词，case-nlp 案例依赖）

### 2.2 opencode

- Node.js LTS（24.x）→ `npm install -g opencode-ai` → `opencode --version`
- **必须在项目根目录打开**（有 `AGENTS.md` 的那一层）
- 选模型：默认免费可跟课
- 练四条命令：`/connect` `/model` `/session` `/compact`
- **工作模式**：对话→改文件→运行，不是网页 Chat 那样只停在对话

### 2.3 第一个脚本

- 接第1节案例：让 opencode 读 `case-nlp/cleaned_300251_comments.csv`（12.4 万条股吧评论）
- 现场生成 `mini_emotion.py`：统计「韭菜」「利好」「崩盘」「涨停」各多少条、最集中在哪年
- 结果：「涨停」6606 条集中 2015、「韭菜」集中 2018——关键词规则不同，"情绪"图景不同，即词典法 vs LLM 法分歧的根源
- **必须点运行且终端无报错**
- 兜底脚本：`case-nlp/mini_emotion.py`

### 2.4 AGENTS.md

- 最简版 3-5 行：项目目标 + 技术栈 + 目录约定
- opencode 打开时自动读取作为上下文——这就是"在项目根目录打开"的原因
- 后续随项目演进逐步完善

## 第3节 · 课堂实验与课后任务布置

> 分组实验：3-4 人一组，每组至少 1 台电脑，组内轮流操作。目标是"感受一次"，人人跑通放在课后。

### 实验一：同题不同问（15 分钟）

- 任务相同：让 opencode 读 `case-nlp/cleaned_300251_comments.csv`，统计「韭菜」「利好」「崩盘」「涨停」关键词分布
- 一半小组用模糊问法："帮我分析一下这些股吧评论"
- 一半小组用明确问法：指定文件路径、date/comment 两列、按年分组、输出格式
- 各组运行后对比：哪次输出更接近想要的？清楚在哪？
- 教师收拢归纳三条经验：**说清楚要什么、给足上下文、给足约束**（体验后带出，不先讲术语）

### 实验二：让 AI 改脚本（10 分钟）

- 让 opencode 把脚本改成词典法每日情绪分数：读 `zhang_unformal_pos.txt` / `zhang_unformal_neg.txt`（与 app.py Part 3 同一份词典），jieba 分词打分，按日汇总
- 输出与第1节 app.py Part 5 每日情绪曲线直接呼应——词典法是什么，学生亲手跑了一遍
- 分词约 1-2 分钟，等待时组内讨论
- 一人键入、其他人盯终端输出、记一句发现
- 卡住顺序：问 AI（附报错）→ 组内互助 → 举手教师
- "对话→改文件→运行"闭环的亲身体验 = 后续科研编程的工作模式底座
- 兜底脚本：`case-nlp/daily_sentiment.py`

### 课后任务布置（12 分钟）

- 环境安装验收（setup.md 六步截图）+ 改造课上脚本（换自己研究方向的关键词/分组维度）+ 最简版 `AGENTS.md`
- 推荐实验：`case-nlp/week01-nlp-lab.ipynb` 亲手做一遍词典法 vs LLM 法，回应课堂疑问
- 课后求助顺序：问 AI（附报错）→ 同学互助 → 课程群提问
- 反思日志第一篇；W2 课前须环境就绪
