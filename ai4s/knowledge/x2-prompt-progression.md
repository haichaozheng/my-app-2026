# Prompt Engineering（贯穿全程）

> **引入时机**：自学（W1起，贯穿全程） | **核心挑战**："与LLM交互的质量决定了AI4S工具栈的输出质量" | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

Prompt Engineering是AI4S工具栈的基础方法论——不是"加分项"，而是"必选项"。无论你使用RAG、Agent还是Skill，底层都是与LLM的交互，而交互质量取决于Prompt质量。一个模糊的Prompt只能得到泛泛而谈的输出，一个精确的Prompt则能产出高度可用的结果。这个差距在科研场景中被进一步放大：科研任务容错率低，一个不当的Prompt可能导致文献综述遗漏关键文献、分析代码包含逻辑错误、论文润色偏离学术规范。

Prompt Engineering不是一成不变的技能，而是随科研阶段演进的。文献综述阶段的Prompt侧重信息提取和综合，选题阶段的Prompt侧重创意激发和可行性评估，分析阶段的Prompt侧重代码生成和结果验证，写作阶段的Prompt侧重语言优化和逻辑审查。每个阶段的Prompt模式都不同，但共享一套底层方法论——角色设定、上下文注入、输出约束、思维链引导等核心技巧贯穿全程。

更重要的是，Prompt Engineering是社科研究者与AI交互的"方法论界面"。你对研究方法的理解越深，你的Prompt就越精准；反过来，写Prompt的过程也迫使你明确自己的方法论选择——"我到底想让AI帮我做什么？为什么这样做？"这种追问本身就是方法论自觉的体现。

## 这个知识点的核心内容

### Prompt Engineering在科研各阶段的进化

**文献综述阶段（W1-W2）**

文献综述的Prompt侧重于信息提取、比较和综合：

```
你是一位社会科学文献综述专家。我正在研究[主题]。
以下是一篇文献的摘要：
[粘贴摘要]

请提取：
1. 研究问题
2. 理论框架
3. 研究方法
4. 核心发现
5. 与我的研究主题的关联

输出格式：结构化的5行表格。
```

批量文献比较的Prompt：

```
以下是我收集的5篇关于[主题]的文献摘要。
请比较它们在以下维度上的异同：
1. 理论视角（功能主义/冲突论/建构主义等）
2. 研究方法（定量/定性/混合）
3. 核心结论（一致/矛盾/互补）
4. 研究局限

请以对比表格形式呈现，并在最后总结研究缺口。
```

**选题阶段（W3）**

选题的Prompt侧重于创意激发和可行性评估：

```
我是一名[学科]博士生，研究兴趣是[领域]。
基于以下文献缺口和研究趋势：
[粘贴文献缺口列表]

请帮我：
1. 生成5个潜在的研究问题，每个问题需说明：
   - 学术贡献（对什么理论有推进）
   - 可行性（数据是否可获取、方法是否成熟）
   - 原创性（与既有研究的差异）
2. 对每个问题按学术贡献、可行性、原创性三个维度打分（1-5分）
3. 推荐最值得深入的2个问题并说明理由
```

**研究设计阶段（W4-W5）**

研究设计的Prompt侧重于方法论证和方案比较：

```
我的研究问题是：[研究问题]
理论框架是：[理论框架]
核心假设是：[假设列表]
可用数据是：[数据描述]

请帮我设计研究方案，要求：
1. 提出2-3种可选的研究方法
2. 每种方法需论证：
   - 为什么这个方法适合回答我的研究问题
   - 需要满足什么前提假设
   - 数据是否满足这些假设
   - 方法的局限性
3. 比较各方案的优劣，推荐最优方案
4. 列出推荐方案的分析步骤
```

**数据分析阶段（W6-W7）**

数据分析的Prompt侧重于代码生成和结果验证：

```
我需要执行以下分析：
[描述分析任务，如"双重差分回归，因变量为Y，处理变量为D，
控制变量为X1-X5，固定效应为firm和year"]

数据格式：
- 文件：CSV，路径为 data/cleaned.csv
- 变量类型：Y(连续), D(0/1), X1(连续), X2(类别), ...

请生成Python代码，要求：
1. 使用statsmodels库
2. 聚类标准误（按firm聚类）
3. 输出回归结果表和效应量
4. 生成系数图
5. 包含数据验证步骤（检查缺失值、变量分布）
```

**论文写作阶段（W8）**

论文写作的Prompt侧重于语言优化和逻辑审查：

```
你是社科领域学术写作专家。请审查以下论文段落的逻辑：
[粘贴段落]

审查维度：
1. 论证链路是否完整（是否有逻辑跳跃）
2. 论据是否充分支撑论点
3. 段落间过渡是否自然
4. 是否有未加引用的事实性论断
5. 是否有循环论证或同义反复

请逐条指出问题并给出修改建议。
```

### 科研场景下的高级Prompt模式

**多轮对话模式**

科研任务往往需要多轮对话逐步深入，而非一次Prompt完成。关键是在后续轮次中提供前文上下文：

```
[第1轮]
用户：请帮我分析这个回归结果。[粘贴回归输出]
LLM：[分析解释]

[第2轮]
用户：你提到可能存在内生性问题。请帮我设计一个工具变量策略。
我想到的候选IV是[描述]。请评估这个IV的合理性。

[第3轮]
用户：好的，请基于这个IV策略生成两阶段最小二乘法的代码。
```

**思维链（Chain-of-Thought）模式**

对于需要推理的科研任务，引导LLM展示推理过程：

```
请帮我评估以下研究设计的内部效度。
请一步一步思考：
1. 首先，识别研究设计的类型
2. 然后，列出该设计面临的主要内部效度威胁
3. 接着，逐一评估每个威胁在本研究中的严重程度
4. 最后，给出改进建议

研究设计描述：[粘贴设计]
```

**元认知Prompt模式**

让LLM反思自身输出的质量：

```
请帮我起草论文的讨论部分。[提供素材]

起草完成后，请自评：
1. 我是否引入了结果部分未呈现的新发现？
2. 我的理论对话是否深入（而非简单引用）？
3. 我是否过度解读了结果（超出数据支撑的范围）？
4. 我的局限性讨论是否诚实和具体？
5. 如果我是审稿人，我会提出什么质疑？

根据自评结果，修改讨论部分。
```

### Prompt的系统化管理和复用

在9周的科研过程中，你会积累大量的Prompt。如果不系统化管理，这些Prompt会散落在各个对话中，无法复用。管理策略：

**策略1：按科研阶段建立Prompt库**

```
prompts/
├── literature/          # 文献综述Prompt
│   ├── extract.md       # 文献信息提取
│   ├── compare.md       # 文献比较
│   └── gap_identify.md  # 缺口识别
├── topic/               # 选题Prompt
│   ├── generate.md      # 研究问题生成
│   └── evaluate.md      # 可行性评估
├── design/              # 研究设计Prompt
│   ├── method_select.md # 方法选择
│   └── design_review.md # 设计审查
├── analysis/            # 数据分析Prompt
│   ├── code_gen.md      # 代码生成
│   └── result_verify.md # 结果验证
└── writing/             # 论文写作Prompt
    ├── draft.md         # 初稿起草
    ├── polish.md        # 润色修改
    └── logic_review.md  # 逻辑审查
```

**策略2：参数化Prompt模板**

将常用的Prompt模式抽象为参数化模板：

```markdown
# 文献信息提取模板

你是一位{discipline}领域的文献综述专家。
我正在研究{research_topic}。
以下是一篇文献的{content_type}：
{content}

请提取：
1. 研究问题
2. 理论框架
3. 研究方法
4. 核心发现
5. 与我的研究主题的关联度（1-5分）

输出格式：{output_format}
```

**策略3：效果日志**

记录每个Prompt的效果，形成个人最佳实践：

```markdown
# Prompt效果日志

## 2024-XX-XX | 文献综述 | 信息提取

Prompt版本：v2（增加了"与我的研究主题的关联度"评分）
效果：关联度评分帮助我快速筛选了50篇文献中的高相关度15篇
改进：下次增加"方法论贡献"维度

## 2024-XX-XX | 数据分析 | 回归代码生成

Prompt版本：v1（未指定聚类标准误）
效果：生成的代码未包含聚类标准误，导致结果与Stata不一致
改进：v2中明确指定"按{cluster_var}聚类标准误"
```

## 关键细节与易错点

- **易错：Prompt过于笼统**。最常见的问题是"帮我分析一下这个数据"——没有说明分析目标、变量含义、预期方法。LLM只能给出泛泛的建议。必须提供充分的上下文和明确的指令。
- **易错：一次性期望完美输出**。复杂科研任务的Prompt通常需要2-3轮迭代。第一轮获取初版，第二轮修正方向，第三轮细化内容。不要期望一次Prompt就得到最终答案。
- **易错：忽略LLM的领域知识局限**。LLM对社科方法论的理解可能不精确。对于专业术语（如"工具变量的排他性约束"），应在Prompt中给出你的理解，让LLM在此基础上工作，而非期望LLM准确理解所有专业概念。
- **易错：不保存有效的Prompt**。当你发现一个Prompt效果很好时，务必保存下来。科研中反复遇到相似任务，复用高效Prompt比重新设计更可靠。
- **易错：忽视Prompt的学科特异性**。经济学Prompt侧重因果推断和识别策略，社会学Prompt侧重理论对话和概念操作化，传播学Prompt侧重效果测量和媒介特征。不同学科需要不同的Prompt设计。

## 社科科研示例

场景：一位社会学博士生研究"社区治理中的居民参与"，展示Prompt在不同阶段的应用。

**文献综述阶段**——理论脉络提取：

```
用户：我正在研究城市社区治理中的居民参与。
以下是3篇核心文献的摘要：
[摘要1: Putnam的社会资本理论视角]
[摘要2: Ostrom的多中心治理理论视角]
[摘要3: Fei的小区治理本土化视角]

请分析这三篇文献之间的理论对话关系：
1. 它们在什么核心问题上存在分歧？
2. 它们各自的理论盲区是什么？
3. 如何整合这些视角构建一个更全面的分析框架？

LLM：[输出理论对话分析，识别出"自组织vs制度设计"的核心分歧，
指出社会资本理论忽视了制度约束，多中心治理理论忽视了中国情境，
费孝通视角缺乏可操作化的分析工具，
建议构建"制度-关系-文化"三维框架]
```

**选题阶段**——可行性评估：

```
用户：我基于上述文献对话，提出以下研究问题：
"城市社区中，制度设计、社会资本和文化传统如何交互影响居民参与治理？"
请评估可行性：
1. 这个问题是否足够聚焦？是否需要缩小范围？
2. 什么研究方法适合回答这个问题？
3. 需要什么数据？数据可获取性如何？
4. 可能面临的核心挑战是什么？

LLM：[建议缩小到"业委会选举参与"作为具体场景，
推荐混合方法（问卷+访谈），
指出数据来源可以是社区调研，
核心挑战是三个维度的交互效应识别]
```

**分析阶段**——代码生成与验证：

```
用户：请生成代码，对我收集的社区问卷数据进行分析：
1. 描述性统计（样本特征、变量分布）
2. 信效度检验（Cronbach's alpha、CFA）
3. 结构方程模型（制度→参与，关系→参与，文化→参与，三个路径）
4. 调节效应检验（制度×关系的交互项）

变量说明：institution(连续,1-5量表), social_capital(连续,1-5量表),
culture(连续,1-5量表), participation(连续,1-5量表)

请使用semopy库，输出标准化系数和模型拟合指标。

LLM：[生成代码，用户运行后与AMOS结果交叉验证]
```
