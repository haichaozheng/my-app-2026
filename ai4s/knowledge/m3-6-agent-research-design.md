# Agent辅助研究设计

> **引入时机**：W5 | **核心挑战**："如何让Agent作为'研究设计顾问'帮我探索设计方案？" | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

研究设计是一个需要多轮推理、反馈和修正的复杂决策过程。你需要从研究问题出发，综合考虑理论框架、方法选择、变量设计、数据可得性等多个维度，最终输出一个逻辑自洽的研究方案。这个过程天然适合Agent——因为Agent可以进行多轮对话、维护上下文、调用工具，并给出结构化的输出。

但Agent不是"替你做研究设计"的工具，而是"辅助你做更好的研究设计"的协作伙伴。Agent可以帮你快速生成方案草案、发现设计漏洞、评估假设合理性，但核心判断——"这个设计是否真的回答了我的研究问题"——必须由你自己做出。

本知识点教你如何设计一个"研究设计顾问"Agent，以及如何与它有效协作。这不是一个现成的工具，而是一套你可以用opencode/cursor构建的工作流。

## 这个知识点的核心内容

### 一、研究设计Agent的设计思路

研究设计Agent的核心逻辑是多轮对话驱动的方案生成与评估：

```
输入：研究问题 + 约束条件
  ↓
多轮对话：
  第1轮：理解研究问题（问题类型、因果层级、理论背景）
  第2轮：生成候选方案（理论框架 + 方法 + 变量设计）
  第3轮：方案评估（假设检验、漏洞识别、替代方案）
  第4轮：方案优化（修正漏洞、补充检验、强化论证）
  ↓
输出：结构化研究方案
```

#### Agent的交互模式

```
模式1：引导式对话（Agent主导）
  Agent: "你的研究问题是什么类型？"
  你: "因果效应估计"
  Agent: "好的，你有处理组和对照组吗？"
  你: "有，政策试点省和非试点省"
  Agent: "这适合DID。你有政策前数据吗？..."
  → 适合：方法探索初期，你不确定方向

模式2：评审式对话（你主导）
  你: "这是我的研究方案，请评估：[粘贴方案]"
  Agent: "方案整体合理，但有以下问题：
          1. 平行趋势假设需要检验
          2. 变量X的测量效度存疑
          3. 遗漏了一个重要的替代解释"
  → 适合：已有初步方案，需要反馈

模式3：协作式对话（共同推演）
  你: "我倾向于用DID，但担心试点选择非随机"
  Agent: "这确实是个问题。你是否考虑PSM-DID？或者找工具变量？"
  你: "PSM-DID可以，但IV不好找"
  Agent: "那PSM-DID加上安慰剂检验可能更实际。另外，
          你可以做异质性分析来增强因果叙事..."
  → 适合：深入讨论具体设计细节
```

### 二、Agent作为"研究设计顾问"的交互策略

#### 策略1：渐进式细化

不要一次性要求Agent给出完整方案，而是逐步细化：

```
第1轮：宽泛探索
Prompt: "我研究[问题]，请帮我梳理可能的研究设计方向，
        不需要细节，只要方向性建议"

第2轮：方向聚焦
Prompt: "我倾向于方向A，请展开这个方向的具体设计框架"

第3轮：细节填充
Prompt: "基于方向A的框架，请帮我设计具体的变量和测量方案"

第4轮：压力测试
Prompt: "请对这个完整方案做压力测试，找出最薄弱的环节"
```

#### 策略2：角色扮演

让Agent扮演不同角色来获得多角度反馈：

```
角色1：严格审稿人
"请你扮演一个顶级期刊的严格审稿人，
 审阅我的研究方案并给出最尖锐的批评"

角色2：方法论专家
"请你扮演一个因果推断方法论专家，
 重点审查我的识别策略是否严谨"

角色3：领域同行
"请你扮演一个[你的学科]领域的资深研究者，
 评估我的研究问题是否有学术贡献"

角色4：魔鬼代言人
"请你扮演魔鬼代言人，
 试图说服我放弃当前的研究设计"
```

#### 策略3：方案对比生成

让Agent同时生成多个方案并对比：

```
Prompt:

请为我的研究问题生成3个不同的研究设计方案：

方案A：使用[方法A]的设计
方案B：使用[方法B]的设计
方案C：混合方法设计

每个方案包含：
1. 理论框架选择
2. 因果识别策略
3. 变量设计
4. 数据需求
5. 预期难点
6. 可行性评分（1-10）

最后，对比三个方案并推荐最优方案。
```

### 三、用opencode/cursor构建研究设计Agent

#### 方案1：使用opencode的Skill

opencode的Skill机制可以封装研究设计的工作流：

```yaml
# research-design-skill.yaml（概念示例）
name: research-design-advisor
description: 研究设计顾问Agent，辅助社科博士生设计研究方案
triggers:
  - "研究设计"
  - "方案评估"
  - "方法匹配"
steps:
  - name: 理解研究问题
    prompt: |
      请仔细阅读用户的研究问题，识别：
      1. 问题类型（描述性/解释性/探索性）
      2. 因果层级（关联/机制/效应）
      3. 学科领域和理论背景
      4. 用户的约束条件

  - name: 生成候选方案
    prompt: |
      基于上一步的分析，生成2-3个候选研究设计方案。
      每个方案包含理论框架、方法选择、变量设计、数据需求。

  - name: 评估与优化
    prompt: |
      对每个候选方案进行评估：
      1. 假设是否可能成立？
      2. 有什么设计漏洞？
      3. 审稿人可能的质疑？
      4. 如何修正？
```

#### 方案2：使用cursor的Composer

在cursor中，你可以用Composer构建多轮研究设计对话：

```
Composer Prompt（第一轮）：

你是一个社科研究设计顾问。你的职责是：
1. 帮助博士生从研究问题出发设计研究方案
2. 评估方案的方法论严谨性
3. 指出设计漏洞并建议修正
4. 诚实讨论局限性

原则：
- 方法选择必须由研究问题驱动，不能反向
- 不回避方法论局限
- 每个推荐都需要给出理由
- 当不确定时，明确说"这需要你自己的判断"

请先询问用户的研究问题和约束条件。
```

#### 方案3：纯Prompt链（最简单）

不依赖任何框架，直接用Prompt链构建：

```
在opencode/cursor的聊天界面中：

Round 1: 粘贴"阶段1：问题描述Prompt"
Round 2: 粘贴"阶段2：约束条件Prompt"
Round 3: 粘贴"阶段3：方法推荐Prompt"
Round 4: 粘贴"阶段4：适用性评估Prompt"

→ 每轮对话基于上一轮的输出，逐步收敛到最终方案
```

### 四、Agent与人类研究者的协作边界

```
Agent应该做的：
  ✓ 快速生成方案草案
  ✓ 系统化地列出假设和检验需求
  ✓ 从审稿人视角发现问题
  ✓ 对比不同方法的优劣
  ✓ 辅助起草方法论证段落
  ✓ 提供方法论文献线索

Agent不应该做的：
  ✗ 替你判断"这个假设是否真的成立"
  ✗ 替你决定"我选哪个方案"
  ✗ 保证方案的可行性（AI无法预知数据中的真实情况）
  ✗ 替你做领域特定的理论判断
  ✗ 替你与导师沟通方案

人类必须做的：
  ★ 最终决策：选择哪个方案
  ★ 假设判断：核心假设是否成立
  ★ 领域判断：理论框架是否适配
  ★ 数据验证：实际数据是否支持设计
  ★ 风险评估：最坏情况下如何应对
```

#### 协作的最佳实践

```
1. 永远不要把Agent的输出直接当最终答案
   → Agent输出是"初稿"，你需要审核、修正、补充

2. 对关键决策做"人机交叉验证"
   → Agent说"DID适合" + 你自己查阅方法论文献确认
   → 两个独立的判断一致时，信心更高

3. 用Agent做"反对者"而非"支持者"
   → 让Agent挑战你的方案，而非让Agent帮你合理化已有选择

4. 记录Agent的建议和你的决策
   → 方案评审时可以展示"我考虑了Agent的X建议，但基于Y原因选择了Z"
   → 这比"我就这么选了"有更强的方法论辩护力
```

## 关键细节与易错点

- **易错：让Agent替你做决策**。Agent是顾问不是决策者。如果你习惯了"AI推荐什么就选什么"，你在放弃研究者最核心的判断力
- **易错：只问Agent一次就定方案**。研究设计需要多轮推演和修正，一次对话不够。至少做"方案生成→评估→优化"三轮
- **易错：忽略Agent的局限性**。Agent不了解你的数据中的真实情况（如缺失值模式、异常值分布），这些需要在实施数据分析后才能发现
- **易错：用Agent生成的方法论证缺乏诚实性**。Agent可能帮你"美化"方法论证，回避局限性。论文中的方法论证必须诚实，否则审稿人会抓住不放
- **易错：Agent的上下文窗口限制**。长对话后Agent可能"忘记"前面的讨论，重要结论需要你主动总结和重述

## 社科科研示例

你是社会学博士生，研究"社区治理参与对居民信任的影响"。

**与Agent的协作过程**：

```
Round 1（问题理解）：
你：我研究社区治理参与对居民信任的影响，数据来自某市12个社区的问卷
Agent：你的问题涉及因果效应估计（参与→信任），但问卷数据是截面的，
       内生性是核心挑战——信任高的居民更可能参与（反向因果）

Round 2（方案生成）：
Agent推荐三个方案：
  方案A：OLS + 控制变量（简单但因果识别弱）
  方案B：IV策略（用"社区是否有参与平台"做工具变量）
  方案C：PSM + 倾向得分匹配（控制可观测选择偏误）

Round 3（压力测试）：
你：请对方案B做压力测试
Agent：
  - 排他性约束是否满足？"社区有参与平台"可能直接影响信任（不仅通过参与）
  - 建议强化论证：社区平台是上级政府统一部署的（外生性更强）
  - 做过度识别检验（如果有多于一个IV）

Round 4（方案优化）：
你：我决定用方案B，排他性约束通过"上级统一部署"论证
Agent：好的。补充建议：
  1. 报告第一阶段F统计量（检验IV强度）
  2. 做IV和OLS结果对比（方向差异本身有信息量）
  3. 增加社区固定效应控制不可观测社区特征
```

最终方案比最初的"跑个OLS"严谨得多，而且Agent的挑战帮助你发现了排他性约束的论证方向。
