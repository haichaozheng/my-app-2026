# 选题对话与验证

> **引入时机**：W4 | **核心挑战**："有了初步想法但不确定是否可行，如何与LLM对话验证？" | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

W3结束时你需要确定选题。你通过gap analysis找到了潜在的研究空白，脑子里有了初步想法，但这个想法是否经得起检验？社科研究中，选题失误是最大的时间浪费——一个不可行的选题可能导致数月的无效劳动，而中途更换选题的成本极高。

很多博士生在选题阶段犯的错误是"爱上自己的第一个想法"。确认偏误让你只看到支持选题的证据，忽略风险信号。你需要系统性地验证选题的可行性，而不是找理由说服自己选题可行。

与LLM对话验证选题，提供了一种低成本、高效率的风险暴露机制。LLM可以扮演反方、测试边界条件、生成替代方案——这些工作自己做既耗时又容易受偏误影响。但对话验证的前提是你有结构化的验证框架，而非随意聊天。掌握这个框架，你能在确定选题前充分暴露风险，做出更可靠的决策。

## 这个知识点的核心内容

### 一、选题可行性验证的四个维度

#### 1. 理论可行性

选题的理论逻辑是否自洽？是否有理论框架支撑？

```
验证问题清单：
- 核心因果机制是否有理论支撑？（不是"我觉得A导致B"，而是"已有理论预测A导致B"）
- 核心假设是否合理？（如果核心假设在理论层面就不成立，研究设计再精巧也无效）
- 预期结论是否有可能推翻已有理论？（如果能，需要更强的证据支撑）
- 理论框架的选择是否为领域主流？（使用边缘理论框架需要额外论证）

判断标准：
- 有明确的理论框架支撑 → 可行性高
- 有理论逻辑但框架不够清晰 → 需要进一步明确
- 缺乏理论支撑、仅靠直觉 → 可行性低，需要重新构思
```

#### 2. 数据可得性

你能否在给定时间内获得所需数据？

```
验证问题清单：
- 核心变量是否有现成的数据来源？（公开数据库/调查数据/爬虫获取）
- 如果需要自行收集数据，收集周期多长？是否在时间约束内？
- 数据样本量是否足够支持你的研究方法？（统计功效分析）
- 数据质量是否满足研究要求？（缺失值、测量误差、样本选择偏误）
- 是否存在数据获取的伦理或法律障碍？

费米估算模板：
目标样本量 = [根据方法计算]
预期可得数据量 = [数据源容量 x 获取成功率 x 有效率]
如果 目标 > 可得 → 数据不可行，需要调整方法或缩小问题
```

#### 3. 方法适用性

你的研究方法是否适合回答研究问题？

```
验证问题清单：
- 研究问题的类型（描述性/解释性/探索性）是否与方法匹配？
- 因果推断方法的前提假设在你的数据中是否可能满足？
  - DID：平行趋势是否可能成立？处理组是否外生？
  - IV：是否存在有效的工具变量？
  - RDD：是否有合适的断点？断点附近样本量是否足够？
- 你是否掌握了该方法的技术实现？（如果不掌握，学习周期多长？）
- 稳健性检验是否可行？（如果只能做一个估计，结论不可靠）

方法匹配矩阵：
| 研究问题类型 | 适用方法 | 不适用方法 |
|---|---|---|
| 因果效应估计 | DID, IV, RDD, PSM | 纯描述性统计 |
| 机制检验 | 中介分析, 调节效应 | 单一回归 |
| 异质性分析 | 分组回归, 交互项 | 仅报告平均效应 |
| 理论建构 | 扎根理论, 案例研究 | 量化回归 |
```

#### 4. 时间约束

在9周的课程框架内，选题的时间预算如何分配？

```
时间预算模板（9周PBL框架）：
W1-W2：文献综述与gap analysis ← 已完成
W3：选题验证与确定 ← 当前阶段
W4：研究设计
W5-W7：数据收集与分析
W8：论文初稿
W9：修改与提交

逆向推算：
- 数据收集最少需要[X]周
- 分析最少需要[X]周
- 写作最少需要[X]周
- → 选题确定后留给执行的时间 = 6周
- → 你的研究设计必须在6周内可执行完毕

如果6周不够 → 选题需要缩小范围或简化方法
```

### 二、与LLM对话验证选题的框架

#### 框架1：反方论证（Adversarial Validation）

让LLM扮演最苛刻的审稿人，从不同角度质疑你的选题。

```
Prompt模板：

"请你扮演一位[顶级期刊]的审稿人，以最严格的标准审查我的选题。

我的选题：[选题完整描述]
核心研究问题：[具体问题]
研究方法：[方法描述]
数据来源：[数据描述]

请从以下角度提出最尖锐的质疑：
1. 理论贡献质疑：这个研究是否只是'换了个情境做同样的事'？
   理论增量在哪里？
2. 因果识别质疑：你声称的因果效应是否能被你的方法识别？
   最可能的替代解释是什么？
3. 数据质量质疑：你的数据是否能支撑你的方法？
   样本选择偏误、测量误差如何处理？
4. 重要性质疑：即使你做出了预期结论，这为什么重要？
   谁会在意？会改变什么？
5. 可行性质疑：这个研究在6周内能完成吗？最可能卡在哪里？

请给出你对这个选题的总体评价：
- 推荐推进 / 有条件推进 / 建议调整 / 建议放弃
- 以及最关键的一条建议"
```

反方论证的核心原则：**不要为自己辩护**。先完整接收所有质疑，再逐一评估哪些质疑是致命的。

#### 框架2：边界条件测试

测试选题在各种边界条件下的稳健性，暴露潜在的脆弱环节。

```
Prompt模板：

"请帮我测试以下选题的边界条件：

选题：[选题描述]

请逐一测试以下边界：
1. 如果核心数据缺失了30%，研究还能做吗？用什么替代？
2. 如果核心方法的前提假设不满足，Plan B是什么？
3. 如果预期结论与假设相反（如效应为零或方向相反），
   这个研究还有意义吗？
4. 如果研究周期从6周缩短到4周，哪些环节可以压缩？
5. 如果只能用公开数据，研究是否仍然可行？
6. 如果该领域在接下来3个月有重要新文献发表，
   最可能推翻我选题的是什么方向的研究？

对每个边界条件，请判断：
- 脆弱（该条件下研究不可行）→ 需要重新设计
- 可恢复（该条件下需要调整但研究仍可行）→ 需要准备Plan B
- 稳健（该条件下研究基本不受影响）→ 可以继续"
```

#### 框架3：替代方案比较

不把选题当作唯一选项，而是与替代方案进行比较。

```
Prompt模板：

"我的选题A：[完整描述]

请基于同样的研究空白，提出2个替代选题：

选题B：[要求AI生成一个方法不同但gap相同的替代方案]
选题C：[要求AI生成一个理论框架不同但现象相同的替代方案]

请从以下维度比较A、B、C：
1. 理论贡献度（1-10）
2. 可行性（1-10，考虑数据、方法、时间）
3. 风险水平（1-10，10为最高风险）
4. 创新性（1-10）
5. 6周内完成概率（%）

最终推荐哪个选题？为什么？"
```

### 三、选题的风险评估：Pre-mortem在选题中的应用

Pre-mortem（事前验尸）是最有力的选题风险评估工具。核心思路：假设选题已经失败，逆推最可能的失败原因。

#### Pre-mortem操作流程

```
Step 1：进入Pre-mortem状态
闭上眼睛，想象现在是W8（距离提交还有1周），你的研究彻底失败了。
不是部分失败——是完全无法得出有意义的结论。

Step 2：逆推失败原因
问自己："最可能导致这个结果的原因是什么？"
列出3-5个最可能的失败原因。

Step 3：评估每个失败原因的概率
- 概率 > 30% → 必须在选题阶段就制定应对方案
- 概率 10-30% → 需要准备Plan B
- 概率 < 10% → 可以接受，但保持警惕

Step 4：制定应对方案
对每个高概率失败原因，设计预防措施和应急方案。
```

#### Pre-mortem与LLM对话的结合

```
Prompt模板：

"请帮我做一个选题Pre-mortem。

我的选题：[选题描述]
研究设计概要：[方法+数据概要]

假设现在是2个月后，这个研究彻底失败了——结论不可靠或无法得出结论。

请列出最可能导致失败的5个原因，按概率从高到低排列。
对每个原因，请：
1. 描述具体的失败场景
2. 估算发生概率（基于你的社科研究经验）
3. 提出预防措施（在选题阶段可以做什么）
4. 提出应急方案（如果真的发生了，如何调整）

请特别注意社科研究中最常见的失败模式。"
```

#### 常见的社科研究失败模式

```
失败模式1：因果识别策略失效
- DID的平行趋势不成立
- IV的外生性假设被质疑
- RDD的断点附近样本量不足
- 预防：在选题阶段就预检验关键假设

失败模式2：数据质量不可控
- 核心变量测量误差过大
- 样本选择偏误无法纠正
- 关键数据突然不可获取
- 预防：在选题阶段就获取数据样本进行质量检查

失败模式3：效应量过小
- 因果效应存在但太小，统计不显著
- 研究结论虽然是"无效应"但缺乏解释力
- 预防：做统计功效分析，确保样本量足够

失败模式4：核心假设被推翻
- 理论框架的关键假设在新数据中不成立
- 预防：检查假设是否有独立的实证支撑

失败模式5：执行时间超预期
- 数据清洗远比预期复杂
- 方法实现遇到技术困难
- 写作时间被压缩
- 预防：每个环节预留20%的缓冲时间
```

### 四、选题验证的决策矩阵

综合四个维度的验证结果，用决策矩阵做最终判断：

```
                理论可行  数据可得  方法适用  时间允许
选题A              +        +        +        +     → 推进
选题A（备选）       +        +        ~        +     → 有条件推进
选题A（调整后）     +        ~        +        ~     → 需要重大调整
选题A              +        -        +        +     → 数据不可行，换题
选题A              -        +        +        +     → 理论不可行，换题

符号说明：
+ = 通过验证    ~ = 有风险但可应对    - = 不通过

规则：
- 任何维度为"-"→ 必须调整或放弃
- 两个及以上维度为"~"→ 需要重大调整
- 所有维度为"+"→ 推进，但仍需准备Plan B
```

## 关键细节与易错点

- **易错：把"可以做"等同于"值得做"**。可行性只是选题的必要条件而非充分条件，一个可行但贡献微弱的研究不如一个稍有风险但贡献显著的研究
- **易错：反方论证后立即修改选题**。先完整听完所有质疑，区分"致命问题"和"可解决的问题"，不要一听到质疑就动摇
- **易错：Pre-mortem变成焦虑放大器**。Pre-mortem的目的是识别风险并制定应对方案，不是让自己陷入决策瘫痪
- **易错：只验证一个选题**。没有比较就没有判断，至少与一个替代选题做对比验证
- **误区：认为验证通过就万事大吉**。验证通过只意味着"目前看不出致命问题"，研究过程中仍可能遇到意外困难
- **误区：忽略自己的能力和兴趣**。选题可行性不仅包括客观条件，还包括你是否真的想做、能否坚持做下去

## 社科科研示例

你是政治学博士生，初步选题为："社交媒体算法对政治极化的因果效应：基于自然实验的实证研究"。

**维度1验证（理论可行性）**：

你向LLM提出反方论证请求。LLM指出：
- "因果效应"的理论机制需要更清晰——算法是通过什么路径导致极化？选择性暴露？回音室？情绪放大？不同机制的实证策略完全不同
- 建议：明确一个核心机制再设计研究

**维度2验证（数据可得性）**：

你向LLM描述数据计划："使用Twitter API获取用户推文数据，用算法变更事件作为准自然实验。"LLM质疑：
- Twitter API在2023年后大幅限制访问，6周内能否获取足够数据？
- 算法变更的精确时间是否公开？如果不知道精确时间点，DID设计不可行
- 即使获取了数据，如何识别用户的政治立场？

你做费米估算：Twitter API免费版每月只能获取1万条推文，远不够DID所需样本。数据可得性评为"~"（有风险）。

**维度3验证（方法适用性）**：

LLM指出：
- 如果用DID，需要算法变更对用户的分配是准随机的——但Twitter的算法变更是全量推送，没有处理组/控制组之分
- 如果用RDD，需要连续变量和断点——但算法变更没有这种结构
- 更合适的方法可能是：利用不同国家/地区的算法变更时间差异做交错DID

方法适用性评为"~"——原来设想的方法不适用，但有替代方案。

**维度4验证（时间约束）**：

6周内完成数据获取+清洗+分析+写作——LLM判断"非常紧张"，特别是数据获取环节不可控。

**Pre-mortem**：

LLM生成最可能的5个失败原因：
1. Twitter API数据获取受阻（概率40%）
2. 算法变更时间信息不足导致DID设计无法实施（概率35%）
3. 政治立场识别方法争议大（概率25%）
4. 效应量太小不显著（概率20%）
5. 时间不够（概率30%）

**决策**：数据维度风险过高，调整选题方向。

**替代选题**：LLM建议改为"信息茧房对政治态度的影响：基于问卷实验的研究"——使用问卷实验替代自然实验，数据自行收集，方法更可控。理论贡献类似但可行性显著提升。

最终你选择了调整后的选题，同时保留了原选题作为长期研究方向。
