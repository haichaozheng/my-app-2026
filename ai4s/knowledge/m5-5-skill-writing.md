# Skill封装写作能力

> **引入时机**：W8 | **核心挑战**："如何把写作辅助流程封装为Skill？" | **层级**：Recommended

## 为什么要在项目阶段学习这个知识点？

在W1-W7的学习中，同学们已经逐步掌握了Prompt Engineering、RAG、Agent和Skill等AI工具栈组件。到了W8论文写作阶段，你会发现一个现象：写作过程中有许多重复性的辅助任务——每次润色段落都要写相似的Prompt，每次调整格式都要重复相同的步骤，每次检查引用都要执行相同的流程。这些重复劳动不仅低效，而且每次Prompt的细微差异会导致输出质量不稳定。

Skill封装写作能力的核心思路是：将反复使用的写作辅助流程固化为可复用的模块，每次调用只需提供变化的部分（如待润色的段落），固定部分（如润色规则、格式要求、学科背景）由Skill自动注入。这就像编程中的函数封装——不是每次都从头写逻辑，而是定义一次、多次调用。

从AI4S方法论的角度看，Skill封装还有更深层意义：它迫使你将隐性的写作知识显性化。当你尝试把润色流程封装为Skill时，你必须明确回答"什么是好的学术写作？我的学科有哪些写作惯例？我期望AI在润色时遵循什么规则？"——这些思考本身就深化了你对学术写作的理解。

## 这个知识点的核心内容

### 写作Skill的设计

写作Skill可以分为三类：润色Skill、格式化Skill和引用管理Skill。

**润色Skill**的设计核心是明确"润色的规则是什么"。一个学术写作润色Skill应包含以下参数化规则：

```markdown
# 学术写作润色Skill

## 角色
你是一位社科领域学术写作润色专家。

## 润色规则
1. 保持作者的原意不变，只优化表达
2. 使用学术语言：精确、客观、有证据支撑
3. 避免口语化表达和模糊量词（如"很多""一些"）
4. 保持术语一致性，同一概念使用同一术语
5. 被动语态和主动语态根据学科惯例选择
6. 段落之间增加逻辑过渡
7. 长句拆分为短句，每句只表达一个核心观点

## 输入参数
- text: 待润色的文本
- discipline: 学科（经济学/社会学/政治学/管理学/传播学）
- section: 所在章节（引言/方法/结果/讨论）
- style: 写作风格（正式/半正式）
- journal: 目标期刊（可选，影响术语和格式偏好）

## 输出格式
返回润色后的文本，并附注修改要点：
- [修改1] 原文→修改后：修改理由
- [修改2] 原文→修改后：修改理由
```

**格式化Skill**的设计核心是明确"目标格式是什么"。例如，将论文从一种引用格式转换为另一种：

```markdown
# 引用格式转换Skill

## 角色
你是一位学术引用格式专家，精通APA、Chicago、GB/T 7714格式。

## 转换规则
1. 严格遵循目标格式的每一项规范
2. 保持所有文献信息完整，不遗漏任何字段
3. 缺失字段用格式要求的方式处理（如省略或标注n.d.）
4. 中文文献和英文文献分别按格式要求处理

## 输入参数
- references: 待转换的参考文献列表
- source_format: 源格式（APA/Chicago/GB-T-7714）
- target_format: 目标格式
- language: 文献语言（中文/英文/混合）

## 输出格式
返回转换后的参考文献列表，按作者姓氏首字母排序。
```

**引用管理Skill**的设计核心是明确"引用完整性检查的规则"：

```markdown
# 引用完整性检查Skill

## 角色
你是一位学术引用完整性审核专家。

## 检查规则
1. 正文中的每条引用是否在参考文献列表中有对应条目
2. 参考文献列表中的每条条目是否在正文中被引用
3. 同一文献在正文中和参考文献中的年份、作者名是否一致
4. 直接引用是否标注页码
5. 多作者引用格式是否正确（如第一作者et al.的使用）

## 输入参数
- main_text: 论文正文
- reference_list: 参考文献列表
- citation_format: 引用格式（APA/Chicago/GB-T-7714）

## 输出格式
返回检查报告：
- 不匹配项列表
- 缺失引用列表
- 格式错误列表
- 修改建议
```

### Skill辅助的写作工作流

将写作流程组织为"起草→润色→格式化→检查"四步工作流，每步对应一个或多个Skill：

**第一步：起草（Draft）**

起草阶段使用通用写作Skill，将研究素材转化为初稿：

```markdown
# 论文章节起草Skill

## 输入参数
- section: 章节名称
- research_question: 研究问题
- key_materials: 核心素材（文献笔记、分析结果、理论要点）
- outline: 该章节的大纲

## 流程
1. 根据outline的各小节，逐节生成初稿
2. 每段以主题句开头
3. 素材中的数据、引用原样保留
4. 章节间逻辑过渡预埋
```

**第二步：润色（Polish）**

润色阶段调用润色Skill，对初稿进行语言优化。关键是**分段润色**而非全文一次润色：

```
调用润色Skill：
- text: [粘贴一个段落的初稿]
- discipline: 社会学
- section: 讨论
- style: 正式
```

**第三步：格式化（Format）**

格式化阶段调用格式化Skill，确保引用格式、标题层级、图表编号等符合目标期刊要求。

**第四步：检查（Check）**

检查阶段调用引用管理Skill和逻辑检查Skill，做最后的质量审核。

### 写作Skill的参数化与复用

Skill的参数化设计决定了其复用能力。一个好的写作Skill应该具有以下特征：

**学科参数化**：同一种润色逻辑，经济学和社会学的术语、风格偏好不同。通过`discipline`参数实现一套Skill服务多个学科。

**章节参数化**：引言的润色侧重论证力度，方法的润色侧重精确性，结果的润色侧重客观性，讨论的润色侧重理论对话深度。通过`section`参数调整润色策略。

**期刊参数化**：不同期刊对论文长度、格式、引用风格有不同要求。通过`journal`参数自动适配。

**语言参数化**：中英文学术写作的惯例不同（如中文更习惯"本文认为"，英文更倾向被动语态）。通过`language`参数切换。

**复用示例**：同一个润色Skill，通过不同参数组合服务不同场景：

```
场景1：经济学论文方法部分润色
→ discipline=经济学, section=方法, style=正式, journal=经济研究

场景2：社会学论文讨论部分润色
→ discipline=社会学, section=讨论, style=正式, journal=社会学研究

场景3：管理学论文引言部分润色（英文）
→ discipline=管理学, section=引言, style=正式, language=英文, journal=AMJ
```

## 关键细节与易错点

- **易错：Skill规则过于笼统**。如果润色规则只写"优化语言表达"，LLM可能过度修改，偏离作者原意。必须具体列出润色的边界——哪些可以改、哪些不能改。
- **易错：忽略学科差异**。不同学科的写作惯例差异很大，一个通用的润色Skill如果不区分学科，可能产出不符合学科惯例的文本。必须通过discipline参数区分。
- **易错：Skill之间缺乏衔接**。起草Skill的输出格式应与润色Skill的输入格式兼容。设计Skill时应考虑整个工作流的数据格式一致性。
- **易错：过度自动化**。不是所有写作步骤都应该自动化。核心的学术判断（如研究贡献的提炼、理论对话的构建）必须由作者自主完成，Skill只辅助工具性环节。
- **易错：Skill版本管理缺失**。随着使用经验增加，你会不断调整Skill的规则。建议使用Git管理Skill文件，记录每次修改的原因和效果。

## 社科科研示例

场景：一位传播学博士生正在撰写关于"算法推荐对信息茧房的影响"的论文，设计了一套写作Skill工作流。

**Skill文件目录**：

```
~/.opencode/skills/
├── academic-polish.md      # 润色Skill
├── citation-check.md       # 引用检查Skill
├── format-convert.md       # 格式转换Skill
└── logic-review.md         # 逻辑审查Skill
```

**润色Skill的实际调用**：

写作讨论部分时，作者先写出核心论点：

> 算法推荐确实加剧了信息茧房效应。我们的发现和之前的研究是一致的，但是我们还发现了一个新的东西，就是用户的主动搜索行为可以抵消算法的影响，这个发现对既有的技术决定论提出了挑战。

调用润色Skill（参数：discipline=传播学, section=讨论）：

> 算法推荐显著加剧了信息茧房效应，这一发现与既有研究一致（Pariser, 2011; Sunstein, 2017）。然而，本研究进一步发现，用户的主动搜索行为对算法驱动的信息窄化具有显著的缓冲效应（β=-0.18, p<0.05）。这一发现对技术决定论视角提出了重要修正：信息茧房的形成并非算法的必然产物，而是算法推荐与用户能动性交互作用的结果。

**逻辑审查Skill的实际调用**：

将全文提交给逻辑审查Skill：

```
输入：
- main_text: [全文]
- research_question: "算法推荐是否加剧信息茧房？用户能动性如何调节这一效应？"
- hypotheses: ["H1: 算法推荐强度与信息茧房程度正相关", "H2: 用户主动搜索行为负向调节算法推荐的影响"]

输出（检查报告）：
1. [不匹配] H1在结果4.1中得到检验，但讨论部分未明确回应H1是否成立
2. [逻辑跳跃] 讨论第3段从"缓冲效应"直接跳到"政策建议"，缺少对缓冲机制的理论解释
3. [建议] 在讨论部分增加一段，基于信息觅食理论解释用户主动搜索的缓冲机制
```
