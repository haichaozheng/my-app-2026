# AI辅助编程（opencode/Cursor/Trae）

> **引入时机**：W1 | **核心挑战**："科研编程效率低，如何用AI加速Python/R/Stata代码编写？" | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

社科博士生在科研中经常需要编程：数据处理用Python或R，计量分析用Stata，文本分析用Python，可视化用各种库。但大多数社科研究者的编程能力是"够用就行"的水平——能写但写不快，能调但调不精。结果是大量时间花在"怎么实现"而非"分析什么"上，而后者才是博士研究的核心价值。

AI编程工具的根本价值在于：它把"怎么实现"的门槛大幅降低，让你把精力集中在"做什么"和"为什么这样做"上。当你想做一个固定效应面板回归，你不需要记住Stata的`xtreg`语法细节，只需要告诉AI"对这份面板数据做固定效应回归"——AI生成代码，你审查逻辑。但这里有一个关键前提：你必须具备判断AI代码"对不对"的方法论素养。AI能帮你"做出来"，但只有你能判断是否"做对了"。

在本课程中，你将使用三类AI编程工具：Cursor/Trae（AI-first IDE，适合交互式开发）、opencode（命令行AI助手，适合项目级代码操作）。掌握它们的正确使用方式，你的科研编程效率可以提升3-5倍，同时保持对代码质量的严格把控。

### 从代码生成到编程搭档的三阶段进化

AI编程工具的进化经历了三个阶段，理解这个进化有助于你正确使用当前工具：

**阶段一：代码补全（Autocomplete）**——AI根据上下文预测下一行代码

特点：被动响应，只在光标位置提供建议。代表：早期GitHub Copilot。

适用：写重复性代码（如数据清洗步骤）、补全标准库调用。

**阶段二：指令式生成（Instruction-based）**——你用自然语言描述需求，AI生成代码块

特点：主动生成，支持多行代码、跨文件编辑。代表：Cursor的Composer、Trae的Builder。

适用：生成完整函数、实现分析逻辑、创建可视化代码。

**阶段三：编程搭档（Coding Partner）**——AI理解项目上下文，主动建议和审查

特点：项目级理解，能识别潜在问题、建议优化方案、解释设计决策。代表：opencode的Agent模式、Cursor的Agent模式。

适用：项目架构设计、跨模块重构、代码审查、调试复杂问题。

当前你应该以"阶段二为主、阶段三为辅"的方式使用工具。即：用指令式生成加速日常编码，用编程搭档模式处理复杂任务。

### 科研场景下的AI编程模式

**数据分析模式**

```python
# 向AI描述需求：
# "读取CFPS2020数据，筛选18-65岁的劳动年龄人口，
#  计算受教育年限（将学历编码转换为年数），
#  按省份汇总平均受教育年限和平均收入"

# AI生成的代码（需要审查）：
import pandas as pd

df = pd.read_stata("cfps2020.dta")

df = df[(df['age'] >= 18) & (df['age'] <= 65)]

edu_years_map = {
    1: 0,    # 未上过学
    2: 6,    # 小学
    3: 9,    # 初中
    4: 12,   # 高中/中专
    5: 15,   # 大专
    6: 16,   # 本科
    7: 19,   # 硕士
    8: 22,   # 博士
}
df['edu_years'] = df['edu_level'].map(edu_years_map)

province_summary = df.groupby('province').agg(
    avg_edu=('edu_years', 'mean'),
    avg_income=('income', 'mean')
).reset_index()
```

审查要点：学历编码映射是否与CFPS代码本一致？年龄和收入的变量名是否正确？缺失值是否需要处理？

**统计建模模式**

```
向AI描述需求：
"我有一份面板数据，想估计数字经济指数对就业率的影响。
 数据结构：province（省份）、year（年份）、digit_index（数字经济指数）、
 employment_rate（就业率）、gdp_per_capita（人均GDP）等控制变量。
 请用Python的linearmodels库做双向固定效应回归，
 并用聚类稳健标准误（按省份聚类）。"
```

AI生成代码后，你审查：固定效应设定是否正确？聚类层级是否合理？控制变量是否遗漏了关键变量？

**文本处理模式**

```python
# 向AI描述需求：
# "对一批政策文本做预处理：分词、去停用词、提取关键词，
#  最终输出每篇文本的TF-IDF关键词列表"

# AI生成代码后，审查要点：
# - 中文分词器是否合适（jieba vs pkuseg）
# - 停用词表是否覆盖社科领域常见无意义词
# - TF-IDF的参数（最大文档频率等）是否合理
```

使用R和tidyverse风格编写代码，遵循以下规范：

### AI调试与代码审查

AI不仅能生成代码，也是强大的调试和审查工具：

**调试流程**：

1. 将完整错误信息（包括traceback）粘贴给AI
2. 要求AI解释错误根因而非仅仅给修复方案
3. 对比AI的修复方案与你对问题的理解是否一致
4. 在修改后用小数据集验证

**代码审查流程**：

```
请审查以下Stata回归代码，检查：
1. 变量操作化是否合理（是否有测量误差）
2. 模型设定是否正确（固定效应、聚类标准误）
3. 是否存在遗漏变量偏误的可能
4. 代码是否有语法错误或逻辑问题

[粘贴代码]
```

这种审查模式特别适合社科场景——AI帮你检查方法论问题，而不只是语法问题。

## 关键细节与易错点

- **易错：直接使用AI生成的统计分析代码而不审查方法论**。AI可能用OLS做了应该用工具变量回归的分析，或者用随机效应做了应该用固定效应的模型。统计方法的选择是研究者的核心判断，不能委托给AI
- **易错：忽略数据编码细节**。社科数据集（如CFPS、CGSS）有复杂的编码规则（-1表示不适用、-2表示拒绝回答等），AI生成的代码可能把这些负值当有效数据处理
- **易错：AI生成Stata代码的质量参差不齐**。相比Python和R，AI对Stata的代码生成质量较低，尤其涉及复杂的面板数据操作和自定义程序时，务必仔细验证
- **易错：混淆不同语言的分析范式**。同一个固定效应模型，Stata用`xtreg`、R用`plm`或`lfe`、Python用`linearmodels`，参数和输出格式都不同。跨语言对照时要格外小心
- **易错：AI"修复"了不该修的东西**。当代码报错时，AI可能修改数据来"解决"问题（如删除缺失值），而非修正分析逻辑。你需要明确告诉AI："不要修改数据，请检查分析方法是否有误"

## 社科科研示例

**场景**：一位社会学博士生需要用Python分析CGSS数据，研究社会资本对主观幸福感的影响。

**步骤1：在Cursor中描述需求，生成数据预处理代码**

```
我有一份CGSS2021数据（Stata格式），需要做以下预处理：
1. 读取.dta文件
2. 筛选有效样本（排除缺失值和拒绝回答的编码：-1, -2, -3, -8, -9）
3. 核心变量：
   - 因变量：幸福感（1-5量表）
   - 自变量：社会资本指数（由3个社交频率变量合成）
   - 控制变量：年龄、性别、教育程度、收入、婚姻状况、城乡
4. 对收入取对数，对年龄取平方项
5. 生成描述性统计表
请给出完整的Python代码。
```

**步骤2：审查AI生成的代码**

关键审查点：
- CGSS的缺失值编码是否全部覆盖？不同变量的缺失编码可能不同
- 社会资本指数的合成方法是否合理？简单加总还是因子分析？
- 教育程度是分类变量还是连续变量？如果是分类，是否需要虚拟变量？

**步骤3：用opencode生成回归分析代码**

```
基于预处理后的数据，执行以下分析：
1. 有序Logit回归（幸福感是1-5的有序变量）
2. 逐步加入控制变量，展示嵌套模型
3. 计算边际效应
4. 输出回归结果表格（含标准误、显著性标记）
```

**步骤4：验证与交叉检验**

用Stata做同样的回归，对比Python和Stata的结果是否一致。如果不一致，排查是数据处理差异还是模型设定差异。
