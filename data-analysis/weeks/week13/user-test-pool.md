# 课程互助测试池使用规则（W11-W14 获客兜底）

> **是什么**：全班互为第一批用户的登记墙。用于真实目标用户触达不足时的兜底渠道，不替代"真实用户"优先原则。
> **何时用**：W11 部署成功后即可登记；W12-W13 触达受阻、W14 反馈收不够 5 条时启用。

## 登记墙

开池后每位同学在一页共享文档里登记一行：

| 字段 | 填什么 |
|---|---|
| 姓名/组别 | |
| 产品链接 | W11 部署成功的公网地址 |
| 我想招募的用户画像 | 如"买基金的散户""找毕业城市的同学" |
| 我能充当谁的用户 | 你能给别人的哪类产品提供真实使用反馈 |
| 联系方式 | 微信/QQ/邮箱 |

## 匹配与承诺

1. **优先跨组匹配**：A 组产品给 B 组同学测，减少人情分
2. 每人承诺：为匹配到的 **≥3 个产品**提供使用反馈，每条反馈注明"同伴测试者"来源
3. 反馈仍按标准分类：功能需求 vs 体验问题（模板见 `templates/peer-review.md` 的反馈格式要求）
4. 测试前给 5 分钟静默使用，不让对方"演示着讲"——才能暴露真实的可用性问题

## 与"真实用户"的关系（计分口径）

- 同伴反馈**可计入**"体验问题"类反馈的兜底数量
- 同伴反馈**不算**"真实目标用户"数——报告里须分开标注来源
- 真实用户仍不足 5 位时：走教师转介（课程群申请，附产品链接与目标画像）；再不足，按 W14 兜底规则以"3 位深度访谈"替代"5-10 条记录"——**评估看深度不看数量**

## 纪律

- 互助测试讲真话：帮同伴找出问题才是赋能"一人公司生态"，客气好评对双方都没用
- 恶意刷差评或拒不履约：教师介入，计入平时成绩沟通项
