# Week 10 教学计划

## 主题
打磨迭代 + 上线部署（首选 Streamlit Cloud）

> **前置**：须已完成 W9 同侪互评并开始打磨。本周完成 v0.4 打磨并**部署上线**——重点是把个人应用真正发到公网：首选 **Streamlit Cloud**（连 GitHub 仓库一键部署、无审核等待、自带 HTTPS，当堂可出 URL）；需要数据库写入、常驻进程或自定义域名的产品走腾讯云自建（进阶）。W11 只做验收与触达，不再新做部署工作。

## 本周学习目标

- 能按反馈优先级排序完成 v0.4 定向打磨，并说明"为什么先做这些"
- 能把 v0.4 部署到 Streamlit Cloud 并公网可访问：说清部署五步（代码上仓 → 依赖清单 → 平台配置 → Secrets 密钥 → 验证 URL）与本地运行的关键区别
- 能说明 Streamlit Cloud 的三个约束（闲置休眠冷启动、资源限额、文件系统临时性）对产品的影响，以及什么时候才需要升级到自建服务器
- 能对照 DSR 七指导原则完成 MVP 阶段自检

## 预计投入
课堂 3×45 分钟。课外 8-10h（首选路线无审核等待，部署本身 30 分钟内可完成；主要时间花在 v0.4 打磨与补齐"依赖、密钥、数据"三件事）

## 教学内容
1. 据反馈定向打磨与技术债清理
2. Streamlit Cloud 部署（首选）：GitHub 仓库 → streamlit.io 一键部署 → Secrets 管理密钥
3. 部署三件事：依赖（`requirements.txt` 冻结）、密钥（`.env` → 平台 Secrets，永不入库）、数据（随仓库 / 启动现场拉取 / 外部存储）；公网 vs 本地的关键区别
4. 托管平台约束：休眠冷启动、资源限额、临时文件系统（SQLite 只读可用，写入会丢）
5. 进阶自建路线：腾讯云轻量/CloudBase（校园免费额度；需数据库写入、常驻进程、自定义域名者）
6. 如何做阶段回顾：DSR 自检可写入本周提交的 `journal.md`，不另开反思文件

## 教学步骤

每周 3 节课，每节 45 分钟（课间另计）。课前：教师演示仓库已推 GitHub 且可一键部署出 URL；`deployment-faq.md` 可投影；v0.4 演示产品能打开；提醒学生确认 W2 建的 GitHub 账号与个人项目仓库可用。

**第1节 · 打磨到可演示（45 分钟）**

1. **分享上周 journal + 互评未改完的先排序（10 分钟）**：随机邀请同学分享上周 journal（3 问：补上了哪个缺口 / 哪个判断不稳 / 下周先解哪个卡点）。随后排未改完的互评项；v0.4=可演示。
2. **打开一台 v0.4（10 分钟）**：Streamlit 看「可演示」长什么样（主路径 3 分钟能走完）。
3. **公网 vs 本地（25 分钟）**：进程常驻、端口、依赖；托管平台 vs 自建服务器的分界（"平台管部署，你管产品" vs "你管一切"）。三个新概念点到即止：①无状态部署——容器重建即清，SQLite 只读可用、写入会丢；②休眠与冷启动——闲置后首访等 10-30 秒，路演前先预热；③密钥从 `.env` 换到平台 Secrets。收束一句："部署就三件事——依赖、密钥、数据。"

**第2节 · 当堂上线：Streamlit Cloud 五步（45 分钟）**

4. **主演示五步（20 分钟）**：①确认代码已在 GitHub 个人仓库（查 `.gitignore`：`.env` 不入库）；②`python -m pip freeze > requirements.txt` 冻结依赖（平台按它装包）；③streamlit.io 用 GitHub 账号登录 → New app → 选仓库/分支/主文件 `app.py`；④Settings → Secrets 配 `TUSHARE_TOKEN`、`DEEPSEEK_API_KEY`（TOML 格式，代码用 `st.secrets["..."]` 读）；⑤Deploy，得到 `*.streamlit.app` 公网 URL——之后 `git push` 自动重新部署。10 分钟内出 URL，让学生看到"当堂上线"。
5. **三类高频报错对照 FAQ（10 分钟）**：`ModuleNotFoundError`（依赖没冻结/漏包）；网页报找不到数据文件（路径写死 `C:\...`、大文件没进仓库→改启动时现场拉取）；AI 功能失效（Secrets 没配/键名不一致）。对照 `deployment-faq.md` 第一、四、五类。
6. **学生跟做部署（15 分钟）**：从 `mvp-template` 或自己的 v0.4 当堂部署；出 URL 者当场把链接发课程群——第一次公网可达。

**第3节 · 部署工作坊 + 方案与自检（45 分钟）**

7. **部署工作坊：人人出 URL（25 分钟）**：学生部署自己的 v0.4；已出 URL 者换手机热点/异地网络各验证一次，并体验冷启动等待；卡住者按第 2 节三类报错自查，三招仍不通带"三件套"（报错截图、执行的命令、部署平台）走互助组/课程群。
8. **部署方案文档（10 分钟）**：五部分——部署目标与公网 URL；路线选择理由（Streamlit Cloud 为何够用/何时不够）；密钥管理方式（Secrets，无一入 git）；数据方案（哪些随仓库、哪些启动现场拉取、哪些将来要外部存储）；升级触发条件（什么情况才需要腾讯云：数据库写入、常驻进程、自定义域名）。
9. **DSR 自检与收束（10 分钟）**：MVP 阶段七原则怎么对照；写进本周提交的 `journal.md`，不另开反思文件。部署成功即触达起点——W11 当堂把链接发班级群/社区，反馈滚到 W14。腾讯云自建为进阶可选。当日在 `journal.md` 追加 1 条（今天做了什么 / 关键决定 / 学习并掌握的新东西 / 卡点 / 互助记录）。互助记录只写「谁帮了你、对项目有何影响」，没有则写「无」。提醒：本周提交截至今日的 `journal.md` 全文作为作业。本周无技能小练。

## 项目活动

**必做**
1. 完成根据互评反馈的定向打磨，产出 v0.4（可演示版）
2. 把 v0.4 部署到 Streamlit Cloud，公网可访问（提交 URL；自建路线部署成功验收等同）
3. 撰写个人上线部署方案（五部分，见第 3 节第 8 步）

**进阶（可选）**
4. 自建路线（腾讯云轻量/CloudBase，校园免费额度——**审核有等待期，周初就申请**）：适合需要数据库写入、常驻进程、自定义域名的产品；两条都走通者写一段资源/运维/成本对比
5. 绑定自定义域名、挂 UptimeRobot 免费可用性监控

**兜底**
- 当堂未出 URL：课后 48h 内对照 `weeks/week10/deployment-faq.md` 排障；仍不通先用 `mvp-template` 部署一个占位 URL 保底，再排查自己的 v0.4；W11 录屏兜底须附补齐计划
