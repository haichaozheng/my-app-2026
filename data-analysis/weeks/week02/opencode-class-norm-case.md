# W2 课堂案例：初步使用 opencode

> 给谁：装好 opencode 之后，第 1 节当场跟做。  
> 教师案例仓库：`data-analysis-showcase`（课程网站）。  
> 你在**自己的项目根目录**跟做前三步；课堂公约可以跟做分析，并看教师用 opencode **改文件、更新网站**（不只是对话）。  
> 规则说明：[opencode 规则 · 初始化](https://opencode.ai/docs/zh-cn/rules/#%E5%88%9D%E5%A7%8B%E5%8C%96)

**必须在项目根目录打开 opencode**（有 `index.html` / 以后有 `AGENTS.md` 的那一层），不要在别的文件夹。

---

## 1. 选模型

界面里选一个即可。

- **默认免费模型可以跟课。**
- 有付费模型或 token plan 的可自行接入。

---

## 2. AGENTS.md

先分清它做什么：`AGENTS.md` 是给 opencode 的**项目规则**。内容会进入模型上下文，用来按本项目定制行为（类似 Cursor 的规则）。

在根目录运行：

```text
/init
```

它会扫描项目并生成 `AGENTS.md`；已经有这份文件，则在原有基础上补充。

**如果是空项目**（几乎还没有代码可扫描），也可以直接让模型生成，例如：

> 这是一个空项目。请在根目录新建 `AGENTS.md`，写清以后怎么运行、代码约定、架构和常见错误。

**也可以把 `journal.md` 的使用规则写进 `AGENTS.md`**，让以后每次对话都记得按这份日志来记，例如：

> 把 `journal.md` 的用法写进 `AGENTS.md`：全学期共用一份，按日追加、旧条目不删；课堂收束写 1 条；五格为今天做了什么 / 关键决定 / 学习并掌握的新东西 / 卡点 / 互助记录；互助只写谁帮了你、对项目有何影响，没有则写「无」。不要替我编日志，提醒我自己写。

生成或补充后**提交进 Git**。

---

## 3. 另三份文件

让 opencode 在根目录生成下面三份，并可按自己的项目补内容：

| 文件 | 写什么 |
|---|---|
| `requirements.md` | 项目的**用户需求**（给谁、解决什么问题、要什么能力） |
| `design.md` | 系统的**技术设计**（怎么实现、用什么结构） |
| `scope.md` | 系统的**功能范围**和开发工作安排（本期做什么、不做什么、按什么顺序） |

可对 opencode 说：

> 在项目根目录新建 `requirements.md`、`design.md`、`scope.md`。requirements 写用户需求，design 写系统技术设计，scope 写功能范围和开发工作安排。

---

## 4. 课堂公约（学生可以跟做一部分）

把 **W1 公约问卷汇总**交给 opencode，和同学一起分析讨论，形成课堂公约，再用 opencode **直接改代码、更新课程网站**（改 showcase 的 `rules.html`），不要停在对话里列条款。

- **学生**：参与讨论；可以跟做「分析问卷 → 让 opencode 改 `rules.html`」这一段（克隆了 showcase 或在自己仓库练同一问法均可）。
- **教师机**：在 `data-analysis-showcase` 根目录让 opencode 改公约页，预览后提交、推送到网站。

**先分析（可贴问卷后一起改）：**

> 下面是本班公约问卷的汇总。请列出主要分歧和可以写进课堂公约的条款，用学生能当场讨论的短句，不要空话。

把问卷汇总贴在后面。全班讨论定稿。

**再落地（同一轮对话里接着做）：**

> 按我们刚定的课堂公约，直接修改 `rules.html` 对应段落，保持现有页面结构和导航。改完说明改了哪几处。不要只给文案。

教师预览公约页，确认后再 git 提交并推送。nav / footer 若被改到，按该仓库 `AGENTS.md` 同步所有 HTML。
