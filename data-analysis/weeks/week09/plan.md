# Week 09 教学计划

## 主题
RAG构建产品知识库（选做）+ 同侪互评 + 开始打磨迭代

> **前置**：须已完成 W8 MVP v0.2（含LLM智能解读）。本周可选升级为RAG问答，同时开始互评与打磨。

## 本周学习目标

- 能基于明确标准（功能完整度/可用性/分析深度/AI功能价值）给组员产品 ≥3 条结构化反馈，其中至少 1 条可执行
- 能说明收到的反馈为什么采纳/为什么不采纳，并落到 v0.3 迭代
- （选做）能说明 RAG 知识库的素材选择、文档切分与检索策略设计理由

## 预计投入

课堂 3×45 分钟。课外 6-8h

## 教学内容
1. RAG构建产品知识库（选做升级：将LLM解读升级为RAG问答，让AI基于专属文档回答）
2. 产品评审标准（功能完整度、可用性、分析深度、AI功能价值）
3. 同侪互评方法（使用 `templates/peer-review.md` 评审单）
4. 据反馈定向打磨与技术债清理

## 课堂演示工具

| 环节 | 工具 | 用法 |
|---|---|---|
| 概念 | 薄幻灯 | 评审四维标准 + 评审单怎么填 |
| 现场主演示 | 学生产品（Streamlit 本地或公网） | 教师用评审单当场评 1 个示例，示范「有维度、有例子、可执行」 |
| 选做短演示 | Trae | RAG：切分一段金融文档 → 问一句 → 看是否引用了文档 |
| 学生主活动 | `templates/peer-review.md` + 产品互评 | 不以教师写代码为主 |

## 教学步骤

每周 3 节课，每节 45 分钟（课间另计）。课前：1 个可打开的示例产品（往届或教师演示）；评审单投影；组员座位按互助组排。

**第1节 · 如何评（45 分钟）**

1. **分享上周 journal + 四维标准（10 分钟）**：随机邀请同学分享上周 journal（3 问：补上了哪个缺口 / 哪个判断不稳 / 下周先解哪个卡点）。四维：功能完整度 / 可用性 / 分析深度 / AI 功能价值。
2. **教师示范评 1 个产品（25 分钟）**：打开产品，用评审单写 ≥3 条（情境–现象–建议），其中 1 条可执行。
3. **RAG 选做（10 分钟）**：切分一段金融文档、问一句、看是否引用文档。不做 RAG 的听完即可。

**第2节 · 组内互评（45 分钟）**

4. **轮转互评（40 分钟）**：组内每人被评；时间凑不齐则先完成 1 人份，其余书面异步、周末补。
5. **中场对齐（5 分钟）**：提醒反馈要有维度、有例子，不要「做得很棒」。

**第3节 · 落到 v0.3（45 分钟）**

6. **采纳/不采纳（20 分钟）**：每人针对收到的反馈写理由，标出本周先改哪 1–2 项。
7. **技能小练（15 分钟）**：`lab.md` 当堂起笔。
8. **收束（10 分钟）**：v0.3=初步打磨；W10 完成可演示的 v0.4。本周不以教师写代码为主。当日在 `journal.md` 追加 1 条（今天做了什么 / 关键决定 / 即时学习 / 卡点 / 互助记录）。互助记录只写「谁帮了你、对项目有何影响」，没有则写「无」。

## 项目活动

**必做**
1. 组内个人MVP互评：基于评审标准给每位组员结构化反馈（书面评审单）
2. 根据互评反馈开始迭代打磨，产出 v0.3——对每条反馈写明采纳/不采纳及理由

**进阶（可选）**
3. 有需要的同学给产品添加RAG功能（选做，知识库素材优先复用W4网页采集的markdown文件和W5的EDA分析结果）

**兜底**
- 小组时间凑不齐：先完成 1 人份完整结构化评审，其余转书面异步反馈，周末前补齐

## 交付物（评分锚点）

- 组内互评反馈（`templates/peer-review.md` 评审单）
- 个人MVP v0.3（含可选RAG升级 + 初步打磨）

—— 规格与知识锚定见 milestones §2.6；计入平时成绩（形成性），并作为期末协作互评的形成性依据。提交前自检：反馈按维度、有等级、有例子？采纳/不采纳有理由？（选做 RAG）切分与检索策略有设计说明？
