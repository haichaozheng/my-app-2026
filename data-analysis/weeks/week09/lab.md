# Week 09 技能小练 — 互评校准 + Skill 创建

> 定位：本周里程碑（组内 MVP 互评 + Skills 开发）的热身，约 30 分钟；计入平时成绩"技能小练"。

## 任务

### Part A：互评校准（15 分钟）

1. 阅读 `templates/peer-review.md` Part A 的四个维度与"情境—现象—建议"格式
2. 对**教师演示产品**（或课堂随机指定的邻组产品）做 10 分钟真实使用——不看作者讲解，自己走一遍核心路径
3. 独立写满一张 Part A：四维度评分各配 1 条观察证据；≥3 条结构化反馈，其中 ≥1 条作者本周内就能改
4. 课堂上与教师的示例评审单对照：你漏掉了什么维度？你的"可执行"真的可执行吗？

### Part B：Skill 创建校准（15 分钟）

1. 在项目根目录创建 `.opencode/skills/<你的skill名>/SKILL.md`
2. 写好 frontmatter：
   - `name`：简短名称
   - `description`：什么任务 + 什么数据 + 什么时候用（这是 AI 判断是否调用的依据）
3. 写好指令正文：场景 → 步骤 → 输出格式
4. 让 AI 帮你做一次这个任务，看输出是否符合预期
5. 如果不符合，修改 SKILL.md 再试一次（迭代改进）

## 提交

- 一张填好的 Part A（评教师产品的这份即可）
- 一个可用的 SKILL.md 文件（在项目 `.opencode/skills/` 目录下）

## 自检（达标线）

### Part A
- [ ] 反馈里没有"感觉不错/有点乱"这类无证据表述
- [ ] 每条建议作者知道明天打开电脑该改哪一行/哪一个控件

### Part B
- [ ] description 写清了「什么任务 + 什么时候用」（不是一句话如"分析文本"）
- [ ] 指令正文有明确的步骤（≥3 步）
- [ ] 有输出格式模板
- [ ] 用 AI 测试过至少一次，确认 Skill 被正确触发
