# 项目日志模板（in-action）— 数据分析与可视化

> **使用说明**：本文件为个人产品仓库内的**即时项目日志**（reflection-in-action）。每次工作或重大事件随手记 3-5 行，记录"此刻发生了什么、我做了什么决定、学到了什么、卡在哪"——帮助你在事后（周反思、最终报告）重构知识，也作为 git 历史（改了什么）与 `requirements/design/scope` 迭代节（触发与 per-artifact 改动）之外的**跨文件决策与学习轨迹**。约 2-3 条/周，按"工作会话"或"重大事件"触发，非每次提交都记。append-only，旧条目不删，只追加。

---

## 与课程其他记录文件的边界

| 文件 | 记录什么 | 频率 |
|---|---|---|
| **journal.md（本文件）** | 跨文件的即时决定 + rationale + 即时学习/卡点 | 工作会话级，频繁轻量 |
| git 提交历史 | 代码"改了什么" | 每次提交 |
| `requirements/design/scope.md` 的迭代N节 | 某 artifact 的触发与改动理由 | 每轮迭代 |
| AGENTS.md | 稳定规则/约定/架构/常见错误 | 原地更新，极少变 |
| 周反思日志（reflection-log.md） | 周度知识重构（on-action） | 每周一份 |

> journal 与周反思互补：journal 是**事中轻记**，周反思是**事后深构**——周反思应综合本周 journal 条目，而非凭空回忆。

---

## 条目格式

```markdown
## [YYYY-MM-DD] 工作会话 / 事件标题
- 做了什么：
- 关键决定：（含备选方案与选择理由；若触发 pivot，写清触发源：用户反馈/越界/新洞察/教师反馈）
- 即时学习：
- 卡点 / 待解：
```

### 示例

```markdown
## [2026-09-22] W4 手动分析流程搭建
- 做了什么：用手动 pandas 跑通了"数据→清洗→单因子洞察"最小闭环，发现缺失值占比 18%
- 关键决定：选"删除缺失行"而非"均值填充"——因为该字段缺失即代表该交易日无成交，填充会伪造信号（备选：前向填充，弃用因会引入未来信息）
- 即时学习：确认偏误自检——我原本只想证明"量价相关"，但分布视角显示相关性很弱，需重新定假设
- 卡点 / 待解：如何把"手动验证过的价值环节"映射成 v0.1 的产品功能？下周 W5 解决
```

---

## DSR 关联提示

- journal 中的"关键决定（含备选与理由）"正是设计科学研究 **Hevner 指导⑥ Design as a Search Process** 的素材：在约束下搜索有效解、记录 why-A-not-B。
- 阶段边界按需把 journal 中反复出现的"卡点/待解"提炼为周反思日志的"知识缺口"，形成 Challenge→Gap→Knowledge→Apply 闭环。
