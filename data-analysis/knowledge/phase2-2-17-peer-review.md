# 同侪互评方法

> **引入时机**：W10 | **核心挑战**："如何有效评价别人的产品？" | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

产品开发不是闭门造车，你需要来自不同视角的反馈来发现问题、获得灵感。同侪互评（Peer Review）让你从评价者和被评价者两个角度受益：评价别人的产品时，你会反思"如果是我会怎么做"，这种对比学习比看教程有效得多；被评价时，你会发现自己盲视的问题——你以为很直观的功能，别人根本找不到入口。

然而，大多数同学不知道如何有效评价别人的产品。"挺好的""不错""可以改进"——这些模糊的反馈毫无价值。同侪互评方法教你如何给出具体、可操作、有建设性的反馈，以及如何从收到的反馈中提炼最有价值的改进方向。

## 这个知识点的核心内容

### 建设性反馈框架

建设性反馈遵循"观察→影响→建议"三步法：

**观察（Observe）**：客观描述你看到了什么
- "首页K线图的颜色是绿色表示上涨"（事实）
- 而非"配色不对"（评价）

**影响（Impact）**：说明这个观察的影响
- "这让我以为股票在下跌，因为国际惯例是绿色表示下跌"
- 而非"让人困惑"（模糊）

**建议（Suggest）**：提出具体的改进建议
- "建议将上涨颜色改为红色，符合中国市场惯例"
- 而非"改一下"（不可操作）

反面示例：
- "挺好的"→ 无信息量
- "感觉不太好"→ 模糊负面
- "你不会用Plotly吗？"→ 攻击性

正面示例：
- "K线图没有均线，影响趋势判断，建议加上MA5和MA20"
- "AI回答没有标注数据来源，无法判断可信度，建议标注参考文档"

### 互评模板

结构化互评模板确保反馈全面且可操作：

```
## 同侪互评表

### 基本信息
- 评审者：[姓名]
- 被评审产品：[产品名称]
- 评审日期：[日期]

### 核心功能评价
- 产品核心功能是：[用一句话描述]
- 核心功能完成度：[1-5分]
- 最印象深刻的功能：[具体描述]

### 做得好的地方（至少2点）
1. [具体描述+为什么好]
2. [具体描述+为什么好]

### 建议改进的地方（至少2点）
1. [观察] → [影响] → [建议]
2. [观察] → [影响] → [建议]

### 各维度评分（1-5分）
- 数据处理：[分] — [一句话理由]
- 分析深度：[分] — [一句话理由]
- 可视化设计：[分] — [一句话理由]
- 用户体验：[分] — [一句话理由]
- AI功能：[分] — [一句话理由]

### 总体评价
- 最突出的亮点：[1点]
- 最需要改进：[1点]
- 一句话总评：[总结]
```

### 互评流程

高效的互评流程：

1. **产品演示（5分钟）**：被评审者演示产品核心功能
2. **自由体验（5分钟）**：评审者自行操作产品
3. **独立填写互评表（5分钟）**：评审者独立评价
4. **面对面反馈（5分钟）**：评审者当面分享反馈
5. **被评审者回应（3分钟）**：感谢+提出追问

关键原则：
- 评审者先独立评价，再讨论，避免从众效应
- 反馈时先说好的，再说改进建议（三明治法则）
- 被评审者倾听为主，不做辩解

### 接收反馈的方法

接收反馈比给出反馈更难，因为你天然会为自己辩护：

**正确姿势**：
- 倾听完整，不打断
- 记录所有反馈，不过滤
- 不理解时追问："你说的'不直观'具体是指哪个操作？"
- 区分事实和观点：事实必须接受，观点可以选择性采纳
- 课后整理：将所有反馈分类为"立即改""以后改""不采纳"

**错误姿势**：
- "你不懂我这个功能的设计意图"（防御性）
- "这个我已经知道了"（轻视反馈）
- 只听好评忽略差评（确认偏误）
- 当场反驳每个建议（浪费时间）

### 反馈的分类与优先级

收到反馈后，按紧急程度和影响程度分类：

```python
feedback_categories = {
    "P0-立即修复": [
        "K线图颜色用反了（红绿颠倒是严重误导）",
        "数据计算有明显错误",
        "核心功能不可用（点击无反应）"
    ],
    "P1-本轮改进": [
        "缺少均线影响趋势判断",
        "AI回答没有来源标注",
        "加载时无提示，以为卡死了"
    ],
    "P2-后续改进": [
        "图表样式可以更美观",
        "希望增加更多股票选择",
        "数据更新频率可以更高"
    ],
    "P3-考虑但不保证": [
        "希望支持自定义指标",
        "希望有暗色模式",
        "希望增加基金分析"
    ]
}
```

### 互评的常见问题

**问题1：互评变成互相吹捧**
- 原因：怕得罪人、期望互给高分
- 解决：明确互评目的不是打分而是改进，匿名评价减少社交压力

**问题2：反馈太模糊**
- 原因：不知道该看什么
- 解决：使用结构化互评模板，逐维度评价

**问题3：只挑毛病不认可优点**
- 原因：认为"好评=客套，差评=认真"
- 解决：明确要求至少写2个优点+2个建议，缺一不可

**问题4：被评审者过度辩解**
- 原因：将反馈视为攻击
- 解决：建立"反馈是礼物"的文化，辩解时间限制在1分钟内

## 关键细节与易错点

- **误区：互评就是给个分数**。互评的核心价值是具体的改进建议，分数只是副产品
- **误区：好评越多越好**。5个模糊好评不如1个具体改进建议有价值
- **易错：只评价表面，不深入使用**。应该实际操作核心功能，而非只看界面
- **易错：用自己产品的标准评价别人**。不同产品有不同的侧重点，应基于产品自身目标评价
- **易错：忽略AI功能的评价**。AI功能是最难评价的部分，应特意测试边界情况（无效输入、幻觉等）

## 金融数据分析示例

使用互评模板评价银行股分析产品：

```
## 同侪互评表

### 基本信息
- 评审者：张三
- 被评审产品：银行股智能分析仪表板
- 评审日期：2024-12-15

### 核心功能评价
- 产品核心功能是：展示银行股K线图和AI问答分析
- 核心功能完成度：4分
- 最印象深刻的功能：AI分析功能可以结合当前股票数据回答问题，
  而非通用闲聊

### 做得好的地方
1. K线图+成交量的双行布局非常专业，底部成交量柱子颜色
   与涨跌一致（红涨绿跌），符合中国市场惯例
2. AI分析标签页的快捷问题按钮（"为什么下跌""估值如何"）
   降低了用户使用门槛，不需要自己想怎么提问

### 建议改进的地方
1. [观察] 多股票对比页面的Y轴范围不一致，
   工商银行5-6元而招商银行30-40元
   → [影响] 直接对比价格走势会误以为工商银行波动更小
   → [建议] 使用归一化收益率而非原始价格做对比，
   或者在图表选项中增加"归一化"开关
2. [观察] AI回答有时会引用不存在的数据，
   如"工商银行2024年Q3净利润同比增长3.2%"
   → [影响] 用户无法判断AI回答是否可靠
   → [建议] AI回答后标注数据来源（如"基于产品内数据"或
   "基于通用知识，请核实"），增加可信度

### 各维度评分
- 数据处理：4分 — 使用AKShare获取数据，有缓存，但未见异常值处理
- 分析深度：3分 — 有K线和基本统计，但缺少行业对比和趋势分析
- 可视化设计：4分 — K线图专业，交互流畅
- 用户体验：4分 — 布局清晰，快捷问题好用
- AI功能：3分 — 能用但有幻觉，缺少来源标注

### 总体评价
- 最突出的亮点：K线图的专业度和AI快捷问题的交互设计
- 最需要改进：AI回答的可信度保障（来源标注+幻觉控制）
- 一句话总评：产品核心功能完整可用，AI功能是差异化亮点，
  但需要增强可信度才能成为真正可信赖的分析工具
```
