# Prompt→RAG→Agent→Skill→评估渐进融入

> **引入时机**：W1→W8→W13→W14 | **核心挑战**：AI工具栈这么多，我该从哪个开始？为什么是这个顺序？ | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

当前AI工具栈的组件越来越多——Prompt、RAG、Agent、Skill、评估——很多学生一上来就想用最复杂的技术，结果在项目早期就被架构复杂性拖垮。本知识点要回答一个关键问题：为什么AI工具栈的引入必须是渐进式的？为什么Prompt是起点，而不是Agent？

渐进式融入的核心逻辑是"需求驱动"。在W1-W3，你连数据长什么样都不清楚，用Agent自动化什么？在W4-W7，你从手动流程到产品原型，需要让AI基于特定金融知识回答问题，这时候RAG才有价值（W8引入构建）。在W8+，当你对任务流程有了清晰认知，Agent才能有效编排。在W13+，当你需要将能力打包复用，Skill才有意义。每个工具的引入时机，应该由项目阶段的需求决定，而非技术热度。

对于财经院校学生，理解这个渐进路径还有一层特殊意义：金融行业正在快速引入AI工具，但大多数从业者对AI工具栈的理解是碎片化的。如果你能系统性地理解从Prompt到Skill的演进逻辑，你在职场中就能成为AI工具落地的推动者，而不仅仅是使用者。

## 这个知识点的核心内容

### AI工具栈的五层渐进模型

```
┌─────────────────────────────┐
│  Layer 5: 评估              │  W14+  验证全链路质量
│  ┌───────────────────────┐  │
│  │  Layer 4: Skill       │  │  W13+  打包能力，复用
│  │  ┌─────────────────┐  │  │
│  │  │  Layer 3: Agent  │  │  │  W8+   编排任务，自动化
│  │  │  ┌───────────┐  │  │  │
│  │  │  │ Layer 2:  │  │  │  │  W4+   知识注入，精准回答
│  │  │  │   RAG     │  │  │  │
│  │  │  │ ┌───────┐ │  │  │  │
│  │  │  │ │Layer 1│ │  │  │  │  W1+   精准表达，高效交互
│  │  │  │ │Prompt │ │  │  │  │
│  │  │  │ └───────┘ │  │  │  │
│  │  │  └───────────┘  │  │  │
│  │  └─────────────────┘  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

### Layer 1: Prompt（W1起）

**为什么是起点**：Prompt是最轻量的AI交互方式，零基础设施，立即可用。所有更高级的工具都建立在有效的Prompt能力之上。

**课程场景**：
- W1-W2：用Prompt探索数据，生成代码，理解金融概念
- W3-W4：用结构化Prompt生成EDA报告和可视化代码
- 贯穿全程：Prompt能力是后续所有层的基础

**关键认知**：如果你的Prompt写不好，RAG注入的知识不会被有效利用，Agent执行的任务会偏离预期，Skill的行为不可控。Prompt是一切的基石。

**何时发现需要升级**：当你发现AI的回答缺乏领域专业性、编造事实、无法基于你的私有数据回答问题时，就需要引入RAG。

### Layer 2: RAG（W4-W8引入）

**为什么在Prompt之后**：RAG解决的核心问题是"AI不知道你的数据"。当项目进入产品构建阶段，你需要AI基于项目特定的金融数据（A股规则、公司财报、历史行情）来回答问题，单纯Prompt无法承载这些知识。

**课程场景**：
- W4-W5：构建金融知识库（A股交易规则、行业分类、财务指标解释）
- W6-W8：将知识库集成到产品中，实现"基于知识的智能问答"

**RAG架构**：
```
用户问题 → 向量化 → 检索知识库 → 组装Prompt（问题+检索结果） → LLM生成回答
```

**关键决策**：
- 向量化模型选择：中文场景推荐text2vec-large-chinese或BGE
- 分块策略：金融文本按段落/条款分块，保留上下文
- 检索策略：混合检索（向量+关键词），top-k=3-5
- 知识库更新：金融数据需要定期更新

**何时发现需要升级**：当你发现任务需要多步骤编排、需要调用外部工具（数据库、API）、需要根据中间结果动态决策时，就需要引入Agent。

### Layer 3: Agent（W8+引入）

**为什么在RAG之后**：Agent解决的核心问题是"复杂任务的多步骤编排"。RAG只能回答知识性问题，但无法执行"获取实时行情→计算指标→生成报告→发送通知"这样的多步骤流程。当你清楚地知道任务的标准流程时，Agent才能有效执行。

**课程场景**：
- W8+：构建自动化分析Agent——定时获取行情→计算技术指标→生成分析报告
- W11+：构建多工具Agent——能调用数据库、API、可视化工具

**Agent架构**：
```
任务描述 → 规划（Planner）→ 选择工具 → 执行 → 观察结果 → 
下一决策 → ... → 汇总输出
```

**关键设计**：
- 工具定义：为Agent提供明确的工具描述（函数名、参数、返回值、用途）
- 决策边界：明确Agent可以自主决策的范围和必须人工确认的操作
- 错误处理：Agent执行失败时的回退策略
- 成本控制：限制Agent的迭代次数，避免无限循环

**何时发现需要升级**：当你发现Agent的某些能力需要在多个场景复用、需要打包成标准化的模块时，就需要引入Skill。

**进阶可选（可复现 Agent 底座）**：如需自托管、且要求分析过程可复现、可审计，可了解 DeepSeek Harness（`dsh`，开源智能体运行框架，提供 Trajectory 轨迹与插件化能力）。对大多数本科生的产品/应用项目，Cursor/Trae/opencode 与 TraeWork/workbuddy 已足够，DSH 仅建议在需搭建可复用分析 Agent 时按需了解。

### Layer 4: Skill（W13+引入）

**为什么在Agent之后**：Skill解决的核心问题是"能力的封装与复用"。当你发现多个Agent/场景需要相似的能力组合（如"股票分析"=数据获取+指标计算+风险评估+报告生成），将这些能力打包为Skill，可以标准化调用、降低复杂度。

**课程场景**：
- W13+：将常用的分析能力封装为Skill，如"每日市场复盘"、"组合风险评估"

**Skill设计**：
```
Skill = 触发条件 + 输入Schema + 处理流程 + 输出Schema + 异常处理

示例：每日市场复盘Skill
- 触发：每日15:30（收盘后）
- 输入：关注的股票列表
- 流程：获取行情→计算涨跌幅→识别异动→生成报告
- 输出：Markdown格式的复盘报告
- 异常：数据源不可用→使用缓存数据+标注数据时间
```

### Layer 5: 评估（W14+引入）

**为什么最后引入**：评估解决的核心问题是"如何验证全链路的质量"。在前面四层都搭建完成后，你需要系统性评估每个环节的输出质量，发现问题并迭代优化。

**评估维度**：
| 层级 | 评估指标 | 方法 |
|------|---------|------|
| Prompt | 准确率、一致性、格式合规率 | 标注测试集+自动比对 |
| RAG | 检索准确率、回答准确率、幻觉率 | 人工评估+LLM-as-Judge |
| Agent | 任务完成率、步骤效率、错误恢复率 | 端到端测试 |
| Skill | 可靠性、延迟、边界情况处理 | 压力测试+回归测试 |

**评估驱动迭代**：
1. 建立评估基准（Baseline）
2. 识别最薄弱的环节
3. 针对性优化
4. 重新评估，确认改进
5. 循环

## 关键细节与易错点

1. **过早引入高级工具**：最常见的错误是在W1就尝试搭建Agent。在你不清楚任务流程之前，Agent只会增加复杂度。先用Prompt手动探索，搞清楚任务流程后，再考虑自动化。

2. **RAG不等于搜索**：RAG的价值不是"搜到相关文档"，而是"将相关知识注入LLM的上下文，使其基于事实回答"。检索质量、分块策略、上下文组装方式都会影响最终效果。

3. **Agent不是万能的**：Agent适合有明确步骤和工具可调用的任务，不适合需要创意或判断力的开放性任务。对于金融场景，涉及投资决策的环节必须由人工审核。

4. **忽视评估**：很多团队搭建了完整的AI工具栈但从不评估。没有评估就没有改进方向。即使是简单的"人工标注50个样本，计算准确率"，也比不评估强得多。

5. **层与层之间不是替代关系**：引入RAG不代表不用Prompt了。每一层都是在前一层基础上增强，不是替代。良好的Prompt仍然是RAG、Agent、Skill的基石。

## 金融数据分析示例

**一个股票分析产品的AI工具栈渐进式搭建过程**：

**W2：Prompt阶段——数据探索**
```python
# 用Prompt生成代码探索A股数据
prompt = "用akshare获取贵州茅台的日线数据，计算20日均线和布林带，画图"
code = call_llm(prompt)
exec(code)
# 发现：AI编造了不存在的akshare接口 → 学习更精确的Prompt
```

**W5：引入RAG——知识问答**
```python
# 构建A股交易规则知识库
docs = ["A股交易时间9:30-15:00", "T+1交易制度", "涨跌幅限制10%/20%...", ...]
vectorstore = create_vectorstore(docs)

# 用户问"科创板股票的涨跌幅限制是多少"
answer = rag_query("科创板股票的涨跌幅限制是多少")
# 输出：基于知识库的准确回答，而非LLM编造
```

**W9：引入Agent——自动化分析**
```python
# 定义工具
tools = {
    "get_stock_data": "获取股票行情数据",
    "calc_technical_indicators": "计算技术指标",
    "generate_report": "生成分析报告"
}

# Agent执行："分析贵州茅台最近一个月的走势"
agent.run("分析贵州茅台最近一个月的走势，给出技术面判断")
# 自动：获取数据→计算指标→生成报告
```

**W13：引入Skill——能力封装**
```python
# 封装为Skill
stock_analysis_skill = Skill(
    name="stock_analysis",
    trigger="用户请求分析股票",
    input_schema={"stock_code": str, "period": str},
    process=[get_data, calc_indicators, assess_risk, gen_report],
    output_schema={"report": Markdown, "risk_level": str}
)
```

**W14：引入评估——质量验证**
```python
# 评估RAG回答质量
test_cases = [
    {"question": "科创板涨跌幅限制", "expected": "20%"},
    {"question": "A股交易时间", "expected": "9:30-11:30,13:00-15:00"},
]
results = evaluate_rag(test_cases)
# 准确率: 85%，主要错误：知识库缺少北交所规则
# 行动：补充北交所规则到知识库
```
