# 产品思维

> **引入时机**：W5-15 | **核心挑战**：我写了一个很酷的程序，但它真的是用户需要的产品吗？ | **层级**：Recommended

## 为什么要在项目阶段学习这个知识点？

大多数学生做项目时的思维路径是"我能做什么技术→我就做什么功能→凑在一起就是产品"。但产品思维要求你倒过来想："用户有什么问题→什么方案能解决→我需要实现哪些功能→技术如何支撑"。这个思维转变是课程项目从"作业"升级为"产品"的关键。

产品思维不是一种天赋，而是一套可学习的方法论。从定义目标用户到识别核心问题，从划定MVP范围到选择关键指标，从收集反馈到迭代优化——每一步都有方法可循。对于财经院校学生，产品思维尤为宝贵：金融行业正在从"产品驱动"转向"用户驱动"，能够站在用户角度设计金融产品的人才极为稀缺。

在PBL课程中，产品思维还扮演着"方向锚定"的角色。17周的项目很容易在技术细节中迷失——加功能、换框架、追新技术。产品思维帮你在每个决策点问一个问题："这对用户有价值吗？"如果没有，就不做。这种聚焦能力是项目成功的保障。

## 这个知识点的核心内容

### 产品思维框架：问题→用户→方案→验证→迭代

**第一步：定义用户**
- 谁是你的目标用户？要具体到"有1-3年投资经验的个人投资者"，而非"投资者"
- 用户画像（Persona）：年龄、收入、投资经验、使用场景、痛点
- 用户的当前解决方案是什么？他们为什么不满？

**第二步：识别问题**
- 用户的痛点是什么？要区分"痒点"（有更好）和"痛点"（必须有）
- 问题的频率和强度：每天遇到 vs 偶尔遇到，很烦 vs 致命
- 问题验证：至少和3个潜在用户聊过，确认问题真实存在

**第三步：设计方案**
- 一句话定位：{目标用户}在{场景}下，通过{方案}解决{问题}
- 核心价值主张：用户选择你而不是现有方案的理由
- 功能优先级：Must-have → Should-have → Nice-to-have

**第四步：MVP验证**
- 最小可行产品：只包含Must-have功能的最小实现
- 验证方式：让5-10个目标用户使用，收集反馈
- 判断标准：用户愿意持续使用 > 用户说"不错"

**第五步：数据驱动迭代**
- 定义北极星指标：最能衡量产品核心价值的单一指标
- 建立反馈循环：使用数据→识别问题→假设原因→实施改进→验证效果
- 迭代节奏：1-2周一个小迭代，每月一个大迭代

### 从问题到产品的旅程

```
问题空间                      解决空间
┌──────────┐               ┌──────────┐
│ 用户痛点  │ ──洞察──→     │ 产品定位  │
│ 使用场景  │               │ 价值主张  │
│ 当前方案  │               │ 功能设计  │
└──────────┘               └──────────┘
     │                          │
     └────验证────┘←────反馈────┘
```

关键原则：
- 在问题空间多花时间：80%的产品失败不是因为技术不行，而是解决了不存在的问题
- 解决空间要克制：功能越少，用户越容易理解核心价值
- 验证要快：不要在用户验证前投入大量开发

### 用户为中心的设计

**用户访谈技巧**：
- 问过去的经历，不问未来的意愿（"你上次分析股票花了多久？" > "你会用这个功能吗？"）
- 问具体的行为，不问抽象的偏好（"你用什么工具看行情？" > "你觉得什么功能重要？"）
- 关注用户的"变通方案"——这揭示了真实需求

**用户旅程地图**：

| 阶段 | 发现 | 评估 | 使用 | 深入 | 流失 |
|------|------|------|------|------|------|
| 触点 | 搜索 | 试用 | 分析 | 组合 | 放弃 |
| 情绪 | 好奇 | 期待 | 满足 | 依赖 | 沮丧 |
| 痛点 | 选择多 | 功能少 | 速度慢 | 深度不够 | 替代品 |
| 机会 | SEO | 快速上手 | 优化 | 高级功能 | 社区 |

**关键指标分层**：

| 指标类型 | 含义 | 金融工具示例 |
|---------|------|------------|
| 获客指标 | 多少人知道并尝试 | 日新增注册用户 |
| 激活指标 | 多少人体验到核心价值 | 首次完成股票分析 |
| 留存指标 | 多少人持续使用 | 周活跃用户/月活跃用户 |
| 变现指标 | 多少人付费 | 付费转化率 |
| 推荐指标 | 多少人推荐给别人 | 邀请注册占比 |

### MVP哲学

MVP不是"粗糙的产品"，而是"最小化的学习工具"：
- 目的不是交付一个不完整的版本，而是以最低成本验证核心假设
- 每个MVP对应一个待验证的假设
- 如果假设被推翻，要能快速调整方向

**MVP设计三原则**：
1. 聚焦一个核心场景：不要试图覆盖所有用户场景，选择最核心的一个做到极致
2. 手动可以，自动化后置：先用人工方式验证流程，确认可行后再自动化
3. 有度量，无猜测：每个功能都要有对应的度量方式，不用猜测判断效果

**金融产品MVP的常见坑**：
- 功能贪多：股票分析+量化回测+社区+资讯 = 什么都做不好
- 忽视数据：花了6周开发但从不看用户数据
- 技术驱动：因为会ML就加预测功能，不管用户是否需要

### 迭代循环

**Build-Measure-Learn循环**：
```
  Build ────→ Measure
    ↑              │
    │              ↓
  Learn ←─────────┘
```

**迭代实践**：
- 每个迭代周期（1-2周）只改一个变量
- 改动前记录假设，改动后用数据验证
- 如果数据不显著，不要急着下结论——可能是样本不够

**金融产品的迭代特殊性**：
- 信任需要时间建立：用户不会第一天就输入真实持仓
- 合规要求可能限制快速迭代：涉及投资建议的功能需要谨慎
- 市场环境变化快：牛市和熊市的用户需求不同

## 关键细节与易错点

1. **把自己当用户**：最常见的错误是"我觉得用户需要这个"。你不是典型用户。去和真正的目标用户聊，观察他们的行为而非听取他们的意见。

2. **功能堆砌代替价值交付**：做了10个功能不代表产品好。用户只关心"我能不能解决我的问题"。一个做到极致的功能胜过10个半成品。

3. **忽视冷启动问题**：产品做好了但没人用。在产品开发的同时就要思考获客策略。对于金融工具，冷启动尤其困难——用户需要信任才会使用。

4. **MVP范围划定不当**：太大（3个月做不完）或太小（验证不了核心价值）。好的MVP是2-4周可交付、能验证核心假设的最小功能集。

5. **只看表面数据**：日活涨了不代表产品好。要看留存率、使用深度、付费转化等质量指标。100个日活+40%留存 > 1000个日活+5%留存。

## 金融数据分析示例

产品思维应用于金融仪表盘的完整过程：

**第一步：定义用户**
```
Persona：李明，28岁，银行客户经理
- 投资经验：2年，主要买基金和少量个股
- 工具：同花顺看行情，Excel做分析
- 痛点：同花顺信息太多找不到重点，Excel做分析太耗时
- 目标：快速判断一只股票值不值得买
```

**第二步：识别问题**
```
核心问题：个人投资者缺乏快速评估股票投资价值的工具
- 现有方案：自己看多维度数据，手动判断 → 耗时30分钟+
- 理想方案：输入股票代码，3分钟内给出综合评估
- 验证：访谈5个同学，3个表示"确实需要"，2个说"不确定"
```

**第三步：方案设计**
```
产品定位：面向1-3年投资经验的个人投资者的智能股票评估工具
核心价值：3分钟内给出一只股票的综合投资评估

功能优先级：
Must-have：
  - 输入股票代码→展示风险评级（高/中/低）
  - 展示3个核心维度的评分（基本面/技术面/资金面）
  - 一句话综合建议

Should-have：
  - 自选股列表
  - 组合风险分析

Nice-to-have：
  - 策略回测
  - 社区讨论
```

**第四步：MVP验证**
```python
# MVP：只有核心评估功能的Streamlit应用
import streamlit as st

st.title("StockLens - 3分钟股票评估")

stock_code = st.text_input("输入股票代码", value="600519")

if st.button("开始评估"):
    with st.spinner("正在分析..."):
        risk = assess_risk(stock_code)  # 风险评级
        scores = calc_scores(stock_code)  # 三维度评分
        summary = gen_summary(risk, scores)  # 综合建议

    st.metric("风险等级", risk)
    col1, col2, col3 = st.columns(3)
    col1.metric("基本面", f"{scores['fundamental']}/10")
    col2.metric("技术面", f"{scores['technical']}/10")
    col3.metric("资金面", f"{scores['capital']}/10")
    st.info(summary)
```

**第五步：迭代计划**
```
V0.1 (W5): MVP - 单股票评估
V0.2 (W7): +自选股列表 +历史评估记录
V0.3 (W9): +组合风险分析 +API化
V0.4 (W11): +因子解释 +深度分析报告
V1.0 (W15): 产品打磨 +性能优化 +Demo准备
```
