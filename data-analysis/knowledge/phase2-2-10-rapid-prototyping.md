# 快速原型方法论

> **引入时机**：W7 | **核心挑战**："如何快速搭建可运行的产品原型？" | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

很多同学在项目阶段陷入"完美主义陷阱"——想先把每个功能都设计好、代码写完美再展示，结果到期末还没拿出一个能运行的东西。快速原型方法论教你如何在最短时间内搭建一个可运行、可演示、可收集反馈的最小可行产品（MVP），然后基于反馈迭代改进。

在金融数据产品的开发中，快速原型尤为重要。你无法预知用户最关心什么功能——是K线图、还是行业对比、还是AI解读。只有把原型放在用户面前，观察他们的使用行为，才能知道该把精力投在哪里。与其花3周做一个完美的K线图组件，不如3天搭一个粗糙但完整的原型，让用户告诉你"我其实更想看相关性分析"。

## 这个知识点的核心内容

### 原型思维

原型思维与传统开发思维的根本区别：

- **传统思维**：规划→设计→开发→测试→发布（瀑布式，追求一次做对）
- **原型思维**：假设→原型→验证→学习→迭代（循环式，追求快速验证）

关键心态转变：
- 从"做完美"到"做得够好就能验证假设"
- 从"功能要全"到"核心功能要先"
- 从"代码要优雅"到"先跑起来再说"
- 从"用户会喜欢"到"让用户告诉我喜不喜欢"

### 核心功能识别

识别核心功能的方法——MoSCoW优先级：

- **Must Have**：没有这个功能产品不成立
- **Should Have**：重要但可以后加
- **Could Have**：锦上添花
- **Won't Have**：本期明确不做

识别Must Have的方法：
1. 写下所有你想做的功能
2. 对每个功能问："如果没有这个，产品还能用吗？"
3. 只保留回答"不能"的——这就是MVP的功能集
4. 再问："这些功能中，哪个最能验证核心假设？"——优先做这个

金融数据产品的典型Must Have：
- 数据获取和展示（没有数据就不是数据产品）
- 至少一种核心分析视图（K线/对比/排名）
- 基本的交互（筛选/缩放）

### 时间盒（Time-boxing）

给每个原型阶段设定严格的时间限制：

- **第1天**：核心数据流跑通（获取→处理→展示）
- **第2天**：核心交互功能（筛选/选择/切换）
- **第3天**：视觉优化和边缘情况处理
- **第4天**：部署和用户测试

时间盒的核心原则：
- 时间到了就必须交付，不管是否完美
- 在有限时间内做最重要的东西
- 超时意味着范围太大，应该缩小而非延长时间

### 从草图到功能原型的演进

**阶段1：纸上草图（30分钟）**

在纸上画出产品的关键页面布局，标注：
- 每个区域放什么内容
- 用户的主要操作路径
- 数据从哪来到哪去

**阶段2：线框图（1-2小时）**

用工具将草图转化为线框图：
- 推荐工具：Excalidraw（手绘风格）、Figma（专业级）、Balsamiq（原型专用）
- 标注交互逻辑：点击A→显示B
- 不需要美观，只需要结构清晰

**阶段3：功能原型（1-3天）**

用Streamlit/Gradio搭建可运行的原型：
- 用真实数据（至少一小部分）
- 核心交互路径可以走通
- 视觉可以粗糙，但功能要可用
- 部署后可以分享给用户

### 原型验收标准

一个合格的原型应该满足：

- **可运行**：不是PPT，是能点击使用的真实产品
- **可演示**：5分钟能向陌生人展示核心价值
- **可反馈**：用户使用后能给出具体的改进建议
- **可迭代**：代码结构允许快速修改和扩展

## 关键细节与易错点

- **误区：原型就是做个简陋版本**。原型的核心是验证假设，不是偷工减料。核心功能的完成度必须高
- **误区：原型做完就不用改了**。原型是迭代的起点，不是终点。预期会做3-5轮迭代
- **易错：功能范围蔓延**。原型阶段不停加新功能，导致核心功能没做完。必须严格执行MoSCoW
- **易错：原型代码太烂无法迭代**。原型代码可以不完美，但基本结构要合理，否则重写比修改快
- **易错：只给自己看不给用户看**。原型的价值在于收集外部反馈，自己觉得好不算好

## 金融数据分析示例

4天搭建股票分析应用原型的计划：

**Day 1：核心数据流**

```python
import streamlit as st
import akshare as ak
import pandas as pd

st.title("银行股分析仪表板")

# 核心功能1：选择股票
stock_code = st.selectbox("选择股票", ["601398", "600036", "601166"])

# 核心功能2：获取和展示数据
@st.cache_data(ttl=3600)
def get_stock_data(code):
    df = ak.stock_zh_a_hist(symbol=code, period="daily",
                            start_date="20240101", end_date="20241231")
    return df

df = get_stock_data(stock_code)
st.line_chart(df.set_index("日期")["收盘"])
st.dataframe(df.tail(10))
```

**Day 2：核心交互**

```python
# 增加日期范围选择
col1, col2 = st.columns(2)
with col1:
    start = st.date_input("开始日期", value=pd.Timestamp("2024-01-01"))
with col2:
    end = st.date_input("结束日期", value=pd.Timestamp("2024-12-31"))

# 增加分析视图切换
view = st.radio("分析视图", ["K线图", "收益率", "行业对比"])

if view == "K线图":
    import plotly.graph_objects as go
    fig = go.Figure(go.Candlestick(
        x=df["日期"], open=df["开盘"], high=df["最高"],
        low=df["最低"], close=df["收盘"]
    ))
    st.plotly_chart(fig, use_container_width=True)
elif view == "收益率":
    df["return"] = df["收盘"].pct_change()
    st.bar_chart(df.set_index("日期")["return"])
```

**Day 3：视觉优化**

- 添加侧边栏布局
- 图表颜色改为中国市场惯例（红涨绿跌）
- 添加关键指标卡片（当前价、涨跌幅、PE）
- 处理加载状态和错误提示

**Day 4：部署与测试**

- 部署到Streamlit Cloud
- 分享链接给3位同学试用
- 收集反馈：最喜欢什么功能？最想加什么功能？哪里不好用？
- 整理反馈，规划下一轮迭代
