# ML基础与模型选择逻辑

> **引入时机**：W11 | **核心挑战**：想给产品加AI预测功能，但不知道选什么模型 | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

当你的金融数据分析产品有了基础的可视化和交互功能后，用户自然而然会提出更高期待："这个股票未来会涨吗？""我的投资组合风险有多大？""这只债券违约概率多高？"这些预测性问题正是机器学习（ML）的用武之地。但面对众多ML模型——线性回归、决策树、随机森林、XGBoost、神经网络——很多同学要么盲目选择最复杂的模型，要么因为不知道怎么选而放弃添加预测功能。

理解ML的基础范式和模型选择逻辑，能帮你根据具体问题类型快速锁定合适的模型方向，避免在模型选择上浪费大量时间。更重要的是，模型选择不是随意的——不同的金融问题对应不同的模型类型，选错模型类型会导致南辕北辙。

在金融领域，ML已经从可选加分项变成了必需能力。从信用评分到量化交易，从欺诈检测到投资组合优化，ML的应用无处不在。理解ML基础不仅是给产品加功能，更是理解现代金融科技的核心思维方式。

## 这个知识点的核心内容

### ML范式概览

机器学习按学习方式分为三大范式：

- **监督学习（Supervised Learning）**：从带标签的数据中学习映射关系。输入特征X，输出标签y。例如：用历史财务数据预测公司是否违约（y=0/1）
- **无监督学习（Unsupervised Learning）**：从无标签的数据中发现结构。例如：对股票进行聚类分组、降维可视化
- **强化学习（Reinforcement Learning）**：通过与环境交互获得奖励来学习策略。例如：交易策略优化、投资组合动态调整

### 模型选择逻辑：问题类型→模型类型

选择模型的第一步不是看模型，而是看问题：

1. **你预测什么？** 连续数值还是离散类别？
   - 预测股价涨跌幅（连续）→ 回归模型
   - 预测股票涨/跌（离散）→ 分类模型
   - 对股票分组（无预先类别）→ 聚类模型

2. **数据长什么样？** 时间序列还是横截面？
   - 有时间顺序的金融数据 → 时间序列模型或带时间特征的监督学习
   - 同一时刻不同个体 → 横截面模型

3. **有多少数据？** 特征数量和样本量的关系
   - 样本量远大于特征数 → 可以用复杂模型
   - 特征数接近或超过样本量 → 需要正则化或降维

4. **可解释性要求？** 黑盒还是白盒
   - 监管要求解释（如信用评分）→ 优先选择可解释模型（逻辑回归、决策树）
   - 只追求预测精度 → 可以用集成模型或深度学习

### 监督学习：回归与分类

这是金融ML应用最广泛的范式：

- **回归问题**：预测连续数值。股价预测、收益率预测、波动率估计、风险敞口计算
- **分类问题**：预测离散类别。信用违约预测（违约/不违约）、涨跌预测（涨/跌/平）、欺诈检测（正常/异常）

### 模型如何学习：梯度下降入门

> 课堂讲授内容（W11）；配套视频 9.3 梯度下降法（超星学习通，见 `video-resources.md`）课后自愿观看。

理解了"选什么模型"之后，还要理解"模型是怎么学会的"——这能帮你解释训练现象、判断过拟合，而不是停留在"调库跑通"。

几乎所有监督学习模型的训练，本质都是一个**最小化损失函数**的优化过程：

- **损失函数（Loss）**：衡量模型预测与真实标签的差距。回归常用均方误差（MSE），分类常用交叉熵。训练的目标就是让损失尽可能小。
- **参数更新**：模型参数（如线性回归的权重）从随机或零初始化出发，沿着损失函数下降最快的方向（负梯度方向）一步步调整：`参数 ← 参数 − 学习率 × 梯度`。
- **收敛**：反复迭代后损失趋于平稳，模型"学会"了数据中的规律。

两个关键直觉（直接支撑过拟合自检）：

- **学习率**：步子太大会震荡不收敛，太小则收敛缓慢。它是"学多快"的旋钮。
- **迭代次数**：迭代太少欠拟合（没学够），迭代太多则可能把训练数据里的噪声也背下来——这正是过拟合的一种机制。训练曲线（训练损失持续降、验证损失先降后升）就是观察这一点的窗口。

在金融场景中：你用历史收益率特征拟合一个回归模型预测下月收益，训练过程就是通过梯度下降（或最小二乘这类等价优化）不断调整权重，让预测误差（MSE）最小。理解了这一点，你就能解释"为什么训练集表现好、测试集崩了"，而不只是报告分数。

### 无监督学习：聚类与降维

在金融中的典型应用：

- **聚类**：股票风格聚类（价值/成长/混合）、客户分群、市场状态识别（牛/熊/震荡）
- **降维**：因子提取（PCA提取市场因子）、特征压缩、高维数据可视化

### 金融领域常见ML应用

| 应用场景 | 问题类型 | 推荐模型类型 |
|---------|---------|------------|
| 信用违约预测 | 二分类 | 逻辑回归、XGBoost |
| 股价方向预测 | 二分类/多分类 | 随机森林、LSTM |
| 收益率预测 | 回归 | 线性回归、Ridge、XGBoost |
| 行业轮动 | 多分类 | 随机森林、梯度提升 |
| 股票聚类 | 聚类 | K-Means、层次聚类 |
| 因子提取 | 降维 | PCA、因子分析 |
| 交易策略优化 | 强化学习 | DQN、PPO |
| 欺诈检测 | 异常检测 | Isolation Forest、One-Class SVM |

## 关键细节与易错点

### 混淆回归和分类

"预测股票涨跌"可以是回归问题（预测涨跌幅的具体数值），也可以是分类问题（预测涨或跌）。选择哪种取决于你的业务需求：如果需要知道具体幅度用回归，如果只需要方向用分类。混淆两者会导致模型选择错误。

### 忽视数据的时间结构

金融数据是时间序列，但很多同学把不同时间的样本当作独立同分布来处理，导致未来数据泄漏（look-ahead bias）。比如用2024年的数据训练来预测2023年的结果。必须按时间顺序划分训练集和测试集。

### 过度追求复杂模型

深度学习不是万能的。在金融领域，简单的线性模型往往因为可解释性和稳健性而优于复杂模型。尤其是在数据量有限的情况下，复杂模型更容易过拟合。从简单模型开始，确认效果后再尝试复杂模型。

### 忽视特征工程

模型选择只是ML流程的一部分，特征工程往往对最终效果影响更大。在金融领域，好的因子（特征）比好的模型更重要。花时间构建有金融逻辑支撑的特征，比调参更有效。

### 样本不平衡

金融分类问题中正负样本往往极度不平衡——违约样本远少于正常样本，暴涨远少于平稳。如果不处理样本不平衡，模型可能把所有样本都预测为多数类而获得很高的"准确率"。需要使用重采样、类权重调整或合适的评估指标（如AUC-ROC）。

## 金融数据分析示例

**场景**：你想给金融分析产品添加两个预测功能：(1) 信用违约预测 (2) 行业ETF月度收益预测。如何选择模型？

**案例1：信用违约预测——分类问题**

问题定义：给定公司的财务指标（资产负债率、流动比率、ROE等），预测其是否会在未来1年内违约。

```
问题类型：二分类（违约/不违约）
数据特点：横截面数据，样本不平衡（违约率约2%）
可解释性要求：高（监管需要解释拒绝贷款的原因）
推荐模型：逻辑回归（基线）→ XGBoost（提升性能）
评估指标：AUC-ROC、Precision-Recall AUC（而非Accuracy）
```

**案例2：行业ETF月度收益预测——回归/时间序列问题**

问题定义：根据历史收益、宏观经济指标、资金流向等特征，预测下月各行业ETF的收益率。

```
问题类型：回归（预测收益率数值）或排序（预测收益率排名）
数据特点：时间序列，样本量中等，特征维度中等
可解释性要求：中（投资者希望理解预测逻辑）
推荐模型：Ridge回归（基线）→ 随机森林/XGBoost → LSTM（如有足量数据）
评估指标：RMSE、方向准确率、IC（信息系数）
```

**模型选择决策流程**：

```python
def choose_model(problem_type, data_size, interpretability_needed):
    if problem_type == "classification":
        if interpretability_needed:
            return "LogisticRegression"
        elif data_size > 10000:
            return "XGBoost"
        else:
            return "RandomForest"
    elif problem_type == "regression":
        if interpretability_needed:
            return "Ridge/Lasso"
        elif data_size > 10000:
            return "XGBoost"
        else:
            return "RandomForest"
    elif problem_type == "clustering":
        return "KMeans"
    elif problem_type == "time_series":
        return "ARIMA/Prophet"
```
