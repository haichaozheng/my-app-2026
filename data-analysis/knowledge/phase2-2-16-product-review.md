# 产品评审标准

> **引入时机**：W9 | **核心挑战**："如何评判数据产品的好坏？" | **层级**：Essential

## 为什么要在项目阶段学习这个知识点？

项目做完了，你怎么知道做得好不好？"感觉还行"不是评判标准。产品评审标准让你从模糊的主观印象走向系统化的客观评估——数据处理的严谨性、分析逻辑的深度、可视化设计的有效性、用户体验的流畅性、AI功能的智能程度，每个维度都有可衡量的标准。

明确评审标准不仅是为了打分，更是为了指导你的开发方向。当你知道"分析深度占30%权重"时，你就不会把全部精力花在UI美化上。评审标准是最好的项目指南针——它告诉你什么重要、什么不重要、做到什么程度算好。

## 这个知识点的核心内容

### 评审维度设计

金融数据产品的评审应覆盖五个核心维度：

**1. 数据处理（20%）**
- 数据来源是否可靠、获取方式是否规范
- 数据清洗是否完整（缺失值、异常值、停牌处理）
- 数据处理逻辑是否正确（复权、对齐、聚合）
- 数据量是否足够支撑分析结论

**2. 分析深度（30%）**
- 分析逻辑是否完整（从问题到结论的推理链）
- 分析视角是否多元（不只看均值，还看分布/趋势/对比/异常）
- 分析结论是否有洞察力（不只是复述数据）
- 是否区分了相关性和因果关系

**3. 可视化设计（20%）**
- 图表类型选择是否恰当
- 图表设计是否遵循金融惯例（红涨绿跌等）
- 交互功能是否支持用户探索
- 信息密度是否合理（不过载也不过简）

**4. 用户体验（15%）**
- 产品是否易于理解和使用
- 功能布局是否合理
- 加载速度和响应速度是否可接受
- 错误处理是否友好

**5. AI功能（15%）**
- AI回答是否基于真实数据（非幻觉）
- Prompt设计是否结构化
- AI功能是否增强了产品价值（非凑数）
- 错误和异常是否有降级处理

### 评分标准与Rubric

为每个维度设计具体的评分等级：

| 维度 | 优秀(90-100) | 良好(75-89) | 及格(60-74) | 不及格(<60) |
|------|-------------|-------------|-------------|-------------|
| 数据处理 | 完整清洗+特殊处理+质量验证 | 基本清洗+复权处理 | 仅基本读取 | 未处理原始数据 |
| 分析深度 | 多视角+有洞察+逻辑链完整 | 2-3个视角+有结论 | 单视角+有图表 | 只有图表没有分析 |
| 可视化 | 类型恰当+交互+金融惯例 | 类型恰当+有交互 | 类型基本正确 | 类型选择错误 |
| 用户体验 | 直觉使用+流畅+美观 | 能用+基本流畅 | 能用但需指导 | 无法正常使用 |
| AI功能 | 基于数据+有洞察+稳定 | 基本可用+偶有幻觉 | 能调用API | 未集成或完全不可用 |

### 自评检查清单

提交产品前，用此清单自检：

**数据处理**
- [ ] 数据获取有错误处理（网络超时、数据不存在）
- [ ] 缺失值已处理（非默认NaN）
- [ ] 异常值已检测和处理
- [ ] 价格数据已复权
- [ ] 停牌日已处理
- [ ] 分组计算未跨股票/跨时间

**分析深度**
- [ ] 有明确的业务问题
- [ ] 从问题到结论有完整推理链
- [ ] 至少从3个视角分析
- [ ] 结论有数据支撑
- [ ] 区分了相关性和因果性

**可视化**
- [ ] 图表类型匹配数据类型
- [ ] 颜色遵循中国市场惯例
- [ ] 关键数据有标注
- [ ] 图表可交互（缩放/筛选/悬浮）
- [ ] 图表大小和字体可读

**用户体验**
- [ ] 新用户5分钟内能理解产品用途
- [ ] 核心功能无需说明书即可使用
- [ ] 加载状态有提示
- [ ] 错误信息用户友好
- [ ] 移动端基本可用

**AI功能**
- [ ] AI回答基于产品数据而非通用知识
- [ ] System Prompt有明确角色和限制
- [ ] 有流式输出
- [ ] API错误有降级方案
- [ ] Token消耗可控

### 评审流程

结构化的产品评审流程：

1. **自评阶段（10分钟）**：产品团队用检查清单自评
2. **演示阶段（8分钟）**：向评审者演示产品核心功能
3. **问答阶段（5分钟）**：评审者提问，产品团队回答
4. **反馈阶段（5分钟）**：评审者给出结构化反馈
5. **评分阶段（2分钟）**：评审者独立打分

演示的结构：
- 30秒：这是什么产品，解决什么问题
- 2分钟：核心功能演示（最重要的一条分析路径）
- 2分钟：亮点功能展示（AI功能/交互设计等）
- 2分钟：技术实现简述
- 1分钟：已知不足和改进计划

### 常见评审问题

评审者通常会问的问题，提前准备：

1. "你的数据从哪来？可靠性如何保证？"
2. "你的分析结论有什么数据支撑？"
3. "如果数据量增加10倍，你的产品还能用吗？"
4. "AI回答不准确时怎么办？"
5. "目标用户是谁？他们真的需要这个功能吗？"
6. "你觉得产品最大的不足是什么？打算怎么改进？"

## 关键细节与易错点

- **误区：评审就是打分**。评审的核心价值是反馈和改进方向，分数只是副产品
- **误区：每个维度都要做到完美**。应聚焦权重最高的维度，分析深度(30%)>数据处理(20%)>可视化(20%)
- **易错：自评时只看自己花了多少时间**。评审看的是产出质量，不是投入时间
- **易错：演示时展示所有功能**。应该聚焦核心功能和亮点，避免平铺直叙
- **易错：对不足遮遮掩掩**。主动承认不足并提出改进计划，比回避问题更得分

## 金融数据分析示例

设计银行股分析产品的评审Rubric：

```python
rubric = {
    "数据处理": {
        "weight": 0.20,
        "criteria": {
            "数据来源可靠性": {
                90: "使用AKShare/Tushare等正规渠道，有错误处理",
                75: "使用正规渠道，但缺少错误处理",
                60: "数据来源不确定，或直接用CSV文件",
                40: "数据来源不明，无任何说明"
            },
            "数据清洗完整性": {
                90: "完整处理缺失值+异常值+停牌+复权",
                75: "处理了缺失值和基本异常值",
                60: "仅简单dropna",
                40: "未做任何清洗"
            },
            "数据处理正确性": {
                90: "所有计算逻辑正确，有验证步骤",
                75: "主要计算正确，细节可能有误",
                60: "基本计算正确，复权等高级处理缺失",
                40: "存在明显计算错误"
            }
        }
    },
    "分析深度": {
        "weight": 0.30,
        "criteria": {
            "分析逻辑完整性": {
                90: "从业务问题到数据结论有完整推理链",
                75: "有分析逻辑但部分环节跳跃",
                60: "有图表但缺少逻辑串联",
                40: "只有图表堆砌，无逻辑"
            },
            "分析视角多元性": {
                90: "4-5个视角（分布/趋势/对比/相关/异常）",
                75: "3个视角",
                60: "1-2个视角",
                40: "只有描述性统计"
            },
            "洞察质量": {
                90: "洞察有业务含义，超出数据表面的描述",
                75: "有结论但缺乏深度",
                60: "只复述数据，如'PE为5.2'",
                40: "无分析结论"
            }
        }
    },
    "可视化设计": {
        "weight": 0.20,
        "criteria": {
            "图表类型": {
                90: "所有图表类型恰当，遵循金融惯例",
                75: "基本恰当，小问题",
                60: "部分图表类型不当",
                40: "图表类型严重错误"
            },
            "交互性": {
                90: "有缩放/筛选/悬浮等交互功能",
                75: "有基本交互",
                60: "静态图表",
                40: "图表无法正常显示"
            }
        }
    },
    "用户体验": {
        "weight": 0.15,
        "criteria": {
            "易用性": {
                90: "无需说明即可使用，布局清晰",
                75: "基本可用，需少量探索",
                60: "需要简单说明才能使用",
                40: "无法正常使用"
            }
        }
    },
    "AI功能": {
        "weight": 0.15,
        "criteria": {
            "AI质量": {
                90: "基于产品数据回答，有洞察，稳定",
                75: "基本可用，偶尔幻觉",
                60: "能调用但回答质量差",
                40: "未集成AI功能"
            }
        }
    }
}

# 计算总分
def calculate_score(scores, rubric):
    total = 0
    for dimension, dim_scores in scores.items():
        weight = rubric[dimension]["weight"]
        avg = sum(dim_scores.values()) / len(dim_scores)
        total += avg * weight
    return total
```
