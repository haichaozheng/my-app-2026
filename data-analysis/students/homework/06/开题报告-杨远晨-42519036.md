## 二、逐维评估（含证据引用）

**1. 问题是否真实具体——充分**
问题锚定在明确场景："目前，绝大多数大学生在备考实习、校招时主要依靠各类求职平台上的面经和真题进行复习……这些资料普遍存在碎片化、分散等特点，难以直观地反映某个岗位的真实考察重点。"（原文），并界定痛点"考点不明、题目分散、缺乏模拟与反馈"。项目目标为"开发一款面向在校大学生的大学生实习&校招笔面试数据分析辅导工具"，边界清楚。

**2. 动机有具体场景与证据——充分**
动机有一手证据：问卷"本次共回收33份有效问卷"，图 2-1 显示"该岗位历年面试高频问题统计"30 人（90.9%）居首；访谈引用同学原话"感觉网上的面经特别零散，我看了很多篇也不知道哪些才是这个岗位最常考的"。证据具体、可核查，用户画像与需求分布清晰。

**3. 调研是否扎实——部分**
报告包含文献调研（2.1.1–2.1.5）、访谈调研与问卷调研（2.2），三类证据齐全且用户侧证据强。但存在两点不足：一是"现有 AI 模拟面试/备考工具"仅以文字描述（"市面上现有的AI模拟面试工具大多采用通用题库，缺乏对真实岗位考情的量化统计依据"），缺少一张竞品/现有方案能力对比表（参照其他报告的表 2-1/2-2 做法）；二是文献与应用之间的串联主要靠"本项目认为……""本项目的解读是……"式的主观解读，缺少一条"痛点→参照→补盲区"的显式推理链与对比取舍。故评为"部分"。

## 三、风险清单与应对（逐条）

原文已提供风险（6.1–6.3），逐条评估：
- 数据采集受限：多源并行+手动+收缩岗位，兜底合理；建议补充"牛客等平台 robots/反爬"的具体合规核查动作。
- 文本质量参差：严格筛选标准+人工抽检，合理。
- AI 出题泛化：强制把考点频次写入 Prompt 并标注对应考点，可执行。
- API 额度/限制：离线预生成模拟题、优先保障看板，务实。
- 合规：仅公开页面、脱敏、项目后删原始文本，但"牛客"等站点的 ToS 与 robots 未显式核验，建议补一句。
- 范围失控：四大核心模块优先，合理。

补充 1 条未覆盖风险：
- **样本时效与代表性偏差**：357 条中互联网技术占 53.2%，且部分岗位样本极少。建议为每类岗位设"最低样本阈值"，低于阈值则在看板明确标注"样本不足，仅供参考"，避免以偏概全（文中已有类似意识，但未写成风险条目）。

## 四、改进建议（必填，具体可执行）

1. **【高】补充"现有 AI 备考工具"系统对比表** → 仿照竞品分析，列 2–3 款现有工具（如市面 AI 面试 App、题库平台）在"真实考情统计/个性化/反馈质量"上的能力与缺口，形成表 → 直接回应"调研扎实"维度，凸显差异化。
2. **【高】建立"痛点→参照→补盲区"显式推理链** → 在 2.3 用一段话把文献结论、访谈发现、问卷数据串成一条逻辑链，并点明本项目填补的具体空白 → 避免文献与应用"各说各话"。
3. **【中】细化数据采集的合规核查** → 明确写出已检查目标站点 robots.txt/ToS、仅采集公开页面、不绕过登录，并保留核查记录 → 降低合规风险被质疑的可能。
4. **【中】明确岗位样本阈值与标注规则** → 为每类岗位设最低样本数（如≥20 条），低于则在看板打"样本不足"标签 → 防止小样本岗位的高频考点误导用户。
5. **【中】AI 反馈质量增加客观校验** → 除用户 1–5 分评分外，增加"AI 给出的薄弱考点与人类教师判定的一致率"作为辅助指标 → 提升"反馈实用性"指标的可信度。
6. **【低】DeepSeek API 成本给出更具体估算** → 列出预计调用次数/令牌量与免费额度覆盖情况，并说明超额时的离线兜底 → 让"成本可控"更可证。
7. **【低】补充"不做清单"** → 仿照其他报告明确列出 5 条不做（如不做简历代写、不做付费题库、不做移动端 App 等）及理由 → 强化边界、控制范围。

## 五、综合结论

**综合评级：A（边缘，B+ 上限）**
总评：用户侧证据（问卷+访谈）扎实、设计与指标具体、风险诚实，是一份完成度很高的应用类开题；主要短板在调研的"系统化对比"与"逻辑串联"上。
