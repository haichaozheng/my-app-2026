## 二、逐维评估（含证据引用）

**1. 问题是否真实具体——充分**
问题通过表 1-1 归纳为四类高频场景（选课、奖学金助学金、宿舍生活、证件补办）及其信息获取痛点，并给出明确问题定义："校园常见问题的信息获取成本高、权威信息分散、人工答疑重复负担重"（原文），同时划定边界"本系统只做'信息查询'，不做'业务办理'；只面向校园公开信息，不涉及个人数据"。真实、具体、高频。

**2. 动机有具体场景与证据——充分**

## 三、风险清单与应对（逐条）

原文风险清单完整（表 6-1，6 条），逐条评估：
- 文档收集不全、大模型幻觉、本地部署性能慢、政策变更致过期、隐私与版权、环境集成失败：触发信号与兜底均具体（如性能慢→换量化小模型/申请免费 API 降级；环境失败→一键脚本/模块化可替换），质量高。
- 补充 1 条未覆盖风险：
  - **FAQ 人工整理的质量与一致性风险**：50 条 FAQ 由单人编写"标准答案"，易引入主观偏差且耗时。建议增加"第二条 FAQ 由同学独立编写后交叉核对"或"答案必须附原文片段"的校验步骤，并把它写入风险表 → 提升准确率指标的可信度。

## 四、改进建议（必填，具体可执行）

1. **【高】降低对单人人工编写 FAQ 的依赖与偏差** → 要求每条 FAQ 的"标准答案"必须挂接原文片段，并邀请 1 名同学独立编写部分 FAQ 做一致性抽查 → 保证测试集准确率与幻觉率指标不被人为抬高。
2. **【高】本地 Ollama 模型性能目标需设更稳妥的兜底** → P90≤15s 对普通笔记本上的本地小模型偏乐观，建议预先在目标机型实测并准备"更小量化模型/限定上下文长度/缓存常见问题答案"三级降级 → 防止演示时响应超时。
3. **【中】幻觉率≤10% 目标偏乐观，建议分阶段** → 先以"检索直出+人工抽检"保证低幻觉，再放开生成；把 10% 设为最终目标、中期设为≤20% → 让指标更贴合本地小模型实际。
4. **【中】知识库覆盖度与"拒答"边界需样例** → 给出 2–3 个"知识库外问题→正确拒答"的真实示例，说明相似度阈值取值依据 → 强化拒答准确率指标的可信度。
5. **【中】补充 FAQ 来源获取的具体路径清单** → 表 5-1 已列类别，建议补"具体栏目 URL/文档名 + 另存为文本的脚本或步骤" → 让"数据可落盘"更可复现。
6. **【低】明确测试集 120 问答对的构建与防泄漏** → 说明问答对是否来自知识库原文、如何避免与检索片段重叠导致准确率虚高 → 提升评估严谨性。
7. **【低】增加"用户满意度"样本代表性说明** → 10–15 名学生中新生/老生比例、是否含留学生等，建议预设抽样结构 → 让满意度结论更稳。

## 五、综合结论

**综合评级：A**
总评：结构规范、证据链完整（人证+参照+技术）、设计与指标具体、风险诚实且有不做清单，是应用类开题的标杆样本。
最关键的两个待改进点：(1) FAQ 由单人编写"标准答案"可能抬高准确率/压低幻觉率，需引入原文挂接与交叉核对；(2) 本地小模型的响应耗时目标偏乐观，应尽早实测并固化降级方案。
