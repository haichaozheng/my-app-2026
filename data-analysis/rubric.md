# 数据分析与可视化 — 评分标准（rubric）

本文件为 `data-analysis-teaching-plan.md` 评分体系提供可操作的量化标准。**凡打分处一律采用百分制(0-100)**；评出的百分制分数再折算为对应分数计入总成绩（总成绩 = 平时成绩 + 个人项目，满分100 = 50 + 50）。平时成绩含其他条目40分与协作互评10分。

## 总成绩公式

```
总成绩 = 平时成绩 + 个人项目                     （满分 100）

平时成绩（满分50） = 平时其他条目 + 协作互评
  平时其他条目（满分40） = 平时其他百分制评分 ÷ 100 × 40
  协作互评（满分10）     = 组内他人打分(百分制)均值 ÷ 100 × 10
      （计入平时，期末评定）

个人项目（满分50）     = 个人项目百分制分 ÷ 100 × 50
    个人项目百分制分 = 产品质量(百分制)×0.6 + 项目报告(百分制)×0.4
```

合计：平时50（其他条目40 + 协作互评10）+ 个人项目50。

> 各周 plan 的"评分锚点（rubric 个人项目·产品质量）"等引用不变：个人项目内部维度不变；协作互评改挂平时。

## 一、平时其他条目（百分制评分，折算满分40分）

教师按百分制综合评分后 ÷100×40 折算。含以下四类，不细分内部比例（由教师按课堂观察与提交记录整体把握）：

| 构成 | 说明 | 主要证据 |
|---|---|---|
| 出勤与课堂参与 | 到课率 + 课堂同侪Critique参与、讨论贡献 | 点名/签到、课堂活动记录 |
| 技能小练（模式A） | 10 次轻量技能练习（W1/W2/W5/W6/W7/W8/W9/W11/W12/W13），各 30-45 分钟，作为相应里程碑的热身；负荷高峰周（W3/W4/W10/W14/W15）与路演收官周（W16/W17）不设 | `weeks/weekXX/lab.md` 提交 |
| 阶段里程碑（模式B，形成性交付） | 提案/手动分析/EDA/可视化/MVP 等 | 各周交付物（见 `milestones.md`，归属"平时/形成性"者） |
| 反思与项目日志 | 项目日志（复制 `templates/journal.md`：今天做了什么 / 关键决定 / 学习并掌握的新东西 / 卡点 / 互助记录；规则见 `templates/journal-rules.md`） | repo 内 `journal.md`（课堂每周记；W3 / W10 / W15 / W17 提交全文） |

**评分要点**：
- 出勤：无故缺课按比例扣减；请假需提前说明。
- 技能小练：完成度、正确性、是否体现当周技能点。
- 里程碑：是否按时提交、是否达到 `milestones.md` 定义的基本规格与知识锚定要求。
- 反思与项目日志：`journal.md` 是否按学习日追加、五格是否写全、关键决定是否含备选与理由（对应 DSR 指导⑥）；W3 / W10 / W15 / W17 是否提交截至当周的全文。
- 形成性（平时）里程碑与终结性（个人项目）里程碑的归属以 `milestones.md` 标注为准，避免同一交付物重复计分。

## 二、个人项目（百分制评分，折算满分50分）

个人项目百分制分 = 产品质量(百分制)×0.6 + 项目报告(百分制)×0.4，再 ÷100×50 折算计入个人项目。

### 2.1 产品质量（百分制评分，占个人项目0.6）

| 维度 | 分值(百分制内) | 评分要点 |
|---|---|---|
| 功能完整度 | 20 | 核心功能可用、数据→分析→建模→可视化的流程闭环 |
| 分析深度 | 15 | 不是图表堆砌，而是从数据到洞察的逻辑推导；批判性思维体现 |
| 分析建模 | 15 | 至少建立 1 个基础模型（回归或分类，必做基础）并合理评估；进阶(时间序列/因子/深度模型)体现更高分析深度 |
| AI功能价值 | 20 | 集成1个LLM/RAG等AI功能（RAG或LLM智能解读二选一）且真实解决用户痛点，而非锦上添花；对AI输出有可信度判断 |
| 路演Demo | 30 | 公开路演中产品价值传达有效性、Demo聚焦核心环节、回答问题表现 |

### 2.2 项目报告（百分制评分，占个人项目0.4）

综合文档，结构见 `templates/final-report.md`，评分：

| 章节 | 分值(百分制内) | 评分要点 |
|---|---|---|
| 产品论证与设计资料 | 30 | 问题定义清晰、方案-问题匹配论证、技术选择有理由、含数据来源与设计资料 |
| 协作贡献记录 | 20 | 按阶段如实记录他人对本项目的具体贡献（阶段/贡献者/具体贡献），可作为互评依据 |
| 用户反馈与获客 | 25 | 是否真实推广给目标用户、反馈分类与分析、对迭代的影响 |
| 最终反思 | 25 | 区分"经历"与"学到的知识"、个人知识框架重构、产品下一步(Scale)思考 |

## 三、协作互评（百分制打分，折算满分10分，计入平时，期末评定）

- **形式**：期末(W17)一次，360°匿名。每人给组内其他每位成员打 **0-100分**。
- **归属**：计入平时成绩，不计入个人项目。
- **计算**：该生协作互评 = 组内他人所打分的算术平均（百分制），÷100×10 折算（均值87.7 → 得8.77分）。
- **依据**：各人项目报告中的"协作贡献"记录（谁在哪个阶段为你做了什么）+ 亲历。
- **印证逻辑**：你帮了谁 → 出现在对方报告的协作贡献栏 → 反映在对方给你的互评分里；你自己报告的协作贡献栏记录的是"谁帮了你"。给与受双向印证。
- **防套利说明**：匿名 + 算术平均。若全组互给高分则人人满分（均匀通胀、彼此公平），但协作差异主要体现在"协作贡献"记录是否被他人真实记名佐证。

> 互评表模板见 `templates/peer-review.md`。

## 计算示例

某5人互助小组，成员甲（所有评分动作均为百分制）：

- 平时其他条目：百分制 88 → ÷100×40 = 35.2 分
- 产品质量：百分制 82；项目报告：百分制 76 → 个人项目百分制分 = 82×0.6 + 76×0.4 = 79.6 → ÷100×50 = 39.8 分
- 协作互评：乙/丙/丁/戊给甲打分 90/85/88/92 → 均值 88.75 → ÷100×10 = 8.88 分

```
平时成绩 = 35.2 + 8.88 = 44.08 分（满分50）
个人项目 = 39.8 分（满分50）
总成绩   = 44.08 + 39.8 = 83.88 分（满分100）
```
