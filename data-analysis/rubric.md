# 数据分析与可视化 — 评分标准（rubric）

本文件为 `data-analysis-teaching-plan.md` 评分体系提供可操作的百分制量化标准。所有分项先按百分制(0-100)评分，再按权重计入总成绩。

## 总成绩公式

```
总成绩 = 平时成绩×0.30
       + 个人项目×0.50      （个人项目 = 产品质量×0.6 + 项目报告×0.4）
       + 协作互评×0.10      （协作互评 = 组内他人匿名打分均值）
       + 组内项目平均×0.10  （组内项目平均 = 组内他人个人项目分均值）
```

个人合计80%、协作合计20%。

---

## 一、平时成绩（30%）

教师综合评分，含以下三类，不细分内部比例（由教师按课堂观察与提交记录整体把握）：

| 构成 | 说明 | 主要证据 |
|---|---|---|
| 出勤与课堂参与 | 到课率 + 课堂同侪Critique参与、讨论贡献 | 点名/签到、课堂活动记录 |
| 技能小练（模式A） | 约8-10次轻量技能练习，作为相应里程碑的热身 | `weeks/weekXX/lab.md` 提交 |
| 阶段里程碑（模式B，形成性交付） | 提案/手动分析/EDA/可视化/MVP/阶段反思日志等 | 各周交付物（见 `milestones.md`，归属"平时/形成性"者） |
| 反思与项目日志 | 周反思日志（`templates/reflection-log.md`，含 feed-forward 缺口闭环、阶段边界 DSR 自检）+ 项目日志（`templates/journal.md`，repo 内 in-action 轻量日志，记跨文件决策与学习轨迹） | repo 内 reflection-log / journal.md（教师抽查，无需单独提交）；阶段边界周反思须含「七、阶段 DSR 自检」 |

**评分要点**：
- 出勤：无故缺课按比例扣减；请假需提前说明。
- 技能小练：完成度、正确性、是否体现当周技能点。
- 里程碑：是否按时提交、是否达到 `milestones.md` 定义的基本规格与知识锚定要求。
- 反思与项目日志：周反思日志是否持续提交、知识缺口是否做 feed-forward 闭环（追踪上周边际是否已补）；项目日志(journal.md)是否持续、决策 rationale（含备选与理由，对应 DSR 指导⑥）质量如何；阶段边界周(W3/W10/W15/W17)反思是否含 DSR 自检（七指导原则命中/缺、知识贡献定位变化、W15 有效性 claim 草稿）。
- 形成性（平时）里程碑与终结性（个人项目）里程碑的归属以 `milestones.md` 标注为准，避免同一交付物重复计分。

## 二、个人项目（50%）

个人项目 = 产品质量×0.6 + 项目报告×0.4，两项均按百分制评分。

### 2.1 产品质量（占个人项目60%，占总成绩30%）

| 维度 | 权重(占产品质量) | 评分要点 |
|---|---|---|
| 功能完整度 | 20% | 核心功能可用、数据→分析→建模→可视化的流程闭环 |
| 分析深度 | 15% | 不是图表堆砌，而是从数据到洞察的逻辑推导；批判性思维体现 |
| 分析建模 | 15% | 至少建立 1 个基础模型（回归或分类，必做基础）并合理评估；进阶(时间序列/因子/深度模型)体现更高分析深度 |
| AI功能价值 | 20% | 集成1个LLM/RAG等AI功能（RAG或LLM智能解读二选一）且真实解决用户痛点，而非锦上添花；对AI输出有可信度判断 |
| 路演Demo | 30% | 公开路演中产品价值传达有效性、Demo聚焦核心环节、回答问题表现 |

### 2.2 项目报告（占个人项目40%，占总成绩20%）

综合文档，结构见 `templates/final-report.md`，评分：

| 章节 | 权重(占报告) | 评分要点 |
|---|---|---|
| 产品论证与设计资料 | 30% | 问题定义清晰、方案-问题匹配论证、技术选择有理由、含数据来源与设计资料 |
| 协作贡献记录 | 20% | 按阶段如实记录他人对本项目的具体贡献（阶段/贡献者/具体贡献），可作为互评依据 |
| 用户反馈与获客 | 25% | 是否真实推广给目标用户、反馈分类与分析、对迭代的影响 |
| 最终反思 | 25% | 区分"经历"与"学到的知识"、个人知识框架重构、产品下一步(Scale)思考 |

## 三、协作互评（10%）

- **形式**：期末(W17)一次，360°匿名。每人给组内其他每位成员打 **0-100分**。
- **计算**：该生协作互评 = 组内他人所打分的算术平均（百分制），÷10 计入总权重。
- **依据**：各人项目报告中的"协作贡献"记录（谁在哪个阶段为你做了什么）+ 亲历。
- **印证逻辑**：你帮了谁 → 出现在对方报告的协作贡献栏 → 反映在对方给你的互评分里；你自己报告的协作贡献栏记录的是"谁帮了你"。给与受双向印证。
- **防套利说明**：匿名 + 算术平均。若全组互给高分则人人满分（均匀通胀、彼此公平），但协作差异主要体现在"协作贡献"记录是否被他人真实记名佐证。

> 互评表模板见 `templates/peer-review.md`。

---

## 四、组内项目平均（10%）

- **计算**：该生组内项目平均 = 组内其他成员"个人项目"百分制成绩（即 产品质量×0.6 + 项目报告×0.4 合并后的百分制分）的算术平均，÷10 计入总权重。
- **含义**：你的成绩与同伴成功绑定，激励一人公司之间的互助赋能。
- **边界**：组内项目平均取自"其他成员"的个人项目分（不含本人）；3人组取另外2人均值，4人组取另外3人均值。

---

## 计算示例

某4人互助小组，成员甲：

- 平时成绩 = 88（教师）
- 个人项目 = 产品质量82×0.6 + 项目报告76×0.4 = 79.6（教师）
- 协作互评 = 组内乙/丙/丁给甲打分 90/85/88 → 均值 87.7 → ÷10 = 8.77
- 组内项目平均 = 乙/丙/丁个人项目分 80/75/82 → 均值 79 → ÷10 = 7.9

```
总成绩 = 88×0.30 + 79.6×0.50 + 8.77 + 7.9
       = 26.4 + 39.8 + 8.77 + 7.9
       = 82.87
```

## 五、评分标准与课程标准映射

本课程四条核心课程标准与评分维度、里程碑证据的对应关系（评估对标准的可追溯性）：

| 课程标准 | 对应评分维度 | 主要里程碑证据 |
|---|---|---|
| ① 理解数据分析流程（采集/清洗/分析建模/可视化） | 产品质量·功能完整度、分析深度、分析建模 | W2 数据源、W6 清洗+EDA、W7 可视化、W12-W15 建模四讲 |
| ② 应用数据分析辅助决策解决实际问题 | 产品质量·分析深度（洞察→决策）、项目报告·用户反馈与获客 | W5 手动分析、W12-W13 用户反馈、W17 反思 |
| ③ 应用 AI 和编程工具完成数据分析产品开发 | 产品质量·功能完整度、AI功能价值；平时·AI辅助编程/AGENTS.md | W1 环境、W8/W9/W11 产品、W9 AI功能 |
| ④ 培养 AI 辅助数据分析与产品设计的素养 | AI功能价值、分析建模(LLM做数据分析)、反思日志、项目日志(journal.md)、AGENTS.md | W6 PromptEDA、W14 LLM分析、W17 反思、journal 决策 rationale、artifact thread |
