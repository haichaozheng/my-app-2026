# 数据分析与可视化 — 个人项目选题指南

本指南是**选题准入门槛**，不替代"选题方法论"。选题方法论（如何判断一个项目值不值得做）见 `knowledge/phase1-1-10-project-screening.md`（Andrew Ng 项目筛选框架）；用户访谈/社区先行方法见 Minimalist Entrepreneur 参考资料。

> 课程核心约束回顾：每人独立完成 1 个产品（一人公司 OPC 模式），17 周，财经本科生（有一定 Python + LLM 应用能力），必须含 1 个 AI 功能（RAG 或 LLM 智能解读二选一），必须公网部署并获取 5-10 位真实用户反馈，领域为**金融 + 社科**。

---

## 1. 选题机制

- **来源有三档**：财经新闻驱动、真实需求驱动、个人爱好。鼓励一个选题能同时命中 ≥2 档（如"财经新闻里的痛点 + 身边人真有此需求"），单靠个人爱好而真实需求不足的，会在 W3 用户访谈中被筛掉。
- **一人一产品**：每位学生独立完成并交付一个自己的产品。
- **互助不要求同领域**：互助小组基于工具 / 方法 / AI 应用互助（互相帮调试、帮选型、帮评审），各人选题可完全不同，仍能互相赋能。
- **教师提供参考菜单**：是启发，非强制、不限制领域。学生完全可以超出菜单。
- **领域**：金融 + 社科（城市 / 政策 / 生活等社科场景均允许，不限于纯金融）。

---



## 2. 选题来源详解



### 2.1 财经新闻驱动

从政策发布、宏观数据、财经事件中提炼话题。

- 来源：央行 / 财政部 / 统计局发布、财经媒体、行业研报摘要。
- 适合：宏观指标解读、行业 / 城市经济画像、政策影响速读。
- 注意：财经新闻给的是"话题热度"，不等于"真实需求"，仍需 W3 验证有人为此痛点付费 / 投入时间。



### 2.2 真实需求驱动

从身边人 / 社区观察到的真实痛点出发（吸收 Minimalist Entrepreneur"社区先行"方法：先去社区，再写代码）。

- 来源：同学、家人、散户 / 求职群体等你能接触到的真实用户。
- 适合：家庭账单解读、基金 / 保险选购解读、买房租房决策、个人理财可视化。
- 优势：用户就在身边，W12 获取 5-10 位反馈最容易，最贴合"公开产品"目标。



### 2.3 个人爱好

从学生自身兴趣出发。

- 来源：你长期关注的行业、你喜欢的某类数据 / 可视化。
- 注意：个人爱好是"动力源"，但单凭爱好容易"有意思却没人要"。务必在 W3 验证真实需求，否则调整。

---



## 3. 选题流程

1. **来源 + 社区调研（W1）**：从三档来源各想 1-2 个方向；进入「后续产品要服务的人」所在场合（线下到场 / 线上旁听 / 需要时再注册），用 `templates/community.md` 交齐调研（原话 ≥3 条）。
2. **候选 2-3 方向（W2）**：列出候选方向但**不锁定**——数据可得性初验（能否免费拿到数据？）与继续倾听并行推进，W3 收敛。
3. **社区先行：继续倾听（W2）**：把 W1 的 `community.md` 迁入仓库；核对人仍是计划服务的人群，原话往下追加。入社区即选题探索，而非事后验证。
4. **数据可得性初验（W2）**：对每个候选方向用 Prompt + AI 辅助编程实拉一次数据，确认能跑通。
5. **从社区调研中形成 / 验证痛点（W3）**：基于社区记录识别痛点，收敛方向；参与社区互动、访谈潜在用户，用 Deep Research 交叉验证，筛掉无真实需求的方向。
6. **W3 项目提案**：用 Andrew Ng 框架论证"为什么值得做"，并通过第 7 节准入清单过审。

> 财经新闻 / 个人爱好类选题若 W3 验证无真实需求，必须调整或重选。

---



## 4. 范围控制

- **量化交易 / 回测允许做**，但必须收敛到一人 12 周可完的 MVP：如单策略回测 + 可视化 + LLM 解读策略逻辑 / 结果，不做全市场投研平台。
- **进阶内容（选做，非必做）**：Agent 自动化、ML / 时间序列、Skill 封装、获客深化（>10 用户）、AI 功能自检。这些让作品从"合格"到"优秀"，但不做不影响及格。
- **通用要求**：提交 MVP 时明确列出"不做"清单（哪些功能本期不做），确保范围在 12 周一人可完。

---



## 5. 否决清单（明令禁止的选题）

1. 需**付费数据**（Wind / Choice / Bloomberg 等，个人不可得）
2. 需**训练模型 / 大量标注**（超出能力与时间）
3. **纯爬虫展示无 AI**（违反"含 1 个 AI 功能"要求）
4. **通用 ChatGPT 套壳**（无专属数据 / 可视化，AI 不 load-bearing）
5. **实时低延迟盯盘**（工程过重，偏离产品思维）
6. **范围过大、一人做不完**（如"全市场投研平台"）

## 7. 选题准入清单（个人项目提案自我审查： 8 项过审）

每项须明确给出，任一不达标即须调整或重选：

1. **数据源**：具体名称 + 已验证可访问的 URL / API（须免费）
2. **用户**：具体人群 + 触达 5-10 人的路径
3. **痛点**：一句话真实痛点（**须来自社区调研 / 用户验证**，附 `community.md` 第 5 节 ≥3 条原话，非假设）
4. **AI 功能**：RAG 还是 LLM 解读，解决哪个具体痛点（非锦上添花）
5. **可视化骨架**：哪 3-5 张图是产品核心
6. **范围**：MVP 在 12 周一人可完，列"不做"清单
7. **部署**：免费方案（Streamlit Cloud / Hugging Face Spaces / Gradio）
8. **合规**：不涉资金交易、不泄露敏感个人数据
